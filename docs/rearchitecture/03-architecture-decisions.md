# ADR 与实施状态

## ADR-008：发布期间有生命周期证明的磁盘身份索引

仅在发布不可变facts/report/provenance时强持有全部根。沿精确内建dict/list/tuple的边，其子对象生命周期被这些容器覆盖，因此object ID不会在本轮复用；将ID到完整有序类型化节点的映射存入SQLite TEMP表，避免同一共享子图超出小型Python缓存后再次展开。TEMP使用文件后备，连接关闭释放；每轮结束/异常清空身份表和强引用缓存。未知容器子类可能返回临时对象，其路径继续只用原有有界强引用缓存，禁止套用该证明。小标量缓存按完整类型及原始字节区分并有界逐出。

不改变权威schema、内容SHA、完整容器比较、类型/顺序/重复次数或原生算法。证据见graph-identity-regression-v1.json的60项专项与graph-publication-f030-v1.json的三个根精确对照；后者只对11.3MB已有原生结果重新入库，显式允许小图内存恢复，不是新提取或大型G1/G3/G4证明。全部全局关系仍须独立优化和实测。封存Portable v9早于此变更。

## ADR-001：本地 Web，继承工作台结构

采用任务书指定 Python + FastAPI + Vue 3/TypeScript + Windows 启动器。静态资源离线分发，终端不需 Node；不采用历史 Qt/逐扫描 HTML 路线。四张旧图只提供信息结构，不使用其虚构数据。新增九导航、人工事件、共享、有效性状态按任务书实现。侧栏232px、顶栏60px，小屏收起侧栏，详情可切换单栏；理由是 1366px/高 DPI 保留搜索和主动作。

## ADR-002：复用既有 WorkspaceResolver

保持项目身份/归属、Junction、外置构建与迁移的单一实现。新增独立用户数据根；旧 tool/project 只能作为显式兼容读取/迁移来源。先验证目标边界，再创建目录。正式流程不得以 legacy 配置继续写固件。

## ADR-003：分层迁移与严格发布阻断

先冻结基线，再实现无损权威库与查询，再迁移消费者。现有旧 CLI 不能通过简单删除 generate 迁移。独立模块可先开发，但消费者、dirty 隔离、完整原生黄金和资源门禁未过时，不宣称正式新扫描链或阶段完成，不将界面做成可点假功能。

## ADR-004：类型化关系树与业务索引

SQLite 保存原始证据的有序类型化节点、容器边与业务关系索引；大型低频文本允许内容寻址压缩。禁止每一事实再存一份完整 JSON。节点哈希去重必须核对内容，不能仅凭哈希合并。业务表引用权威节点，未知字段通过有序树无损往返。该编码是实现候选，只有完整往返/关系查询/峰值测量通过后才能用于正式发布；不是已验证的70%收益。

## ADR-005：人工记录与静态证据正交

scan.db 发布后只读；reviews.db 存不可变事件和独立修复状态。事件形成 predecessor DAG；同一对象存在多个分支头即冲突，禁止按时间覆盖。只有相同 scan/项目/完整证据指纹才能导入；新扫描证据变化使用 RECHECK_REQUIRED。确认者是用户声明，界面明确未认证。

## ADR-006：证据分组与固定人工操作

真实浏览器attempt3截图显示，全部折叠字段纵向排列仍把人工按钮推到长页末尾，不满足H5的固定主要操作。保留左38%/右62%、身份/时序/访问优先的冻结结构，把右侧改为有界滚动证据区，分组为时序与访问、调用与保护、归档源码、人工历史；人工确认表单与按钮稳定保留在详情底部。未来字段仍可从完整对象索引逐段读取，不删除证据。小屏采用单栏，浏览器截图只证明相应视口，不代替Windows系统DPI验收。前后截图都保留。

## ADR-007：真正的任务、证据和空间整理

正式新扫描保留原引擎全套构建/输入/发布门禁，写唯一scan.db，AI和人工事件独立。每任务隔离目录与工程锁覆盖持久化验收、人工历史关联和latest发布；失败不改变上一有效指针。重复扫描从同profile已校验库读取完整finding ID，不把原有项误标新增。消费者的旧逻辑文件名只是精确只读适配，不能作为完整JSON副本重新写出；显式--legacy-output仅用于兼容验证。

任务中心继承阶段/资源/日志/底部操作结构。任务存在时配置可收起、阶段和日志分别滚动，停止/恢复操作在本面板底部保持可见，避免配置挤走主操作。资源预算使用Windows Job Object聚合提交限制，数据根内跨实例预算锁；软阈值只影响新TU调度并保持数据库顺序，临近硬阈值请求安全停止。此实现不构成32GB机器性能通过。

工作台保持38/62默认双栏和独立人工操作，增加可拖动及键盘调整分隔线。静态理由、真实关系参与者和行号源码窗口优先展示；完整字段、长行和全部调用边仍能分页读取。潜在交错明确为归档推断；缺少关系不解释成安全。IDE链接仅在本机扫描且原文件SHA仍相同时提供，无任意shell或文件读取接口。

清理先对所有静态/AI/人工/审计引用及内容校验，再生成持久SQLite候选计划，仅处理已发布无引用CAS和Resolver持有的可重建TU缓存。独占数据锁内重新校验后逐文件隔离，支持移动中崩溃恢复；永久释放另需确认，出现新引用则恢复或保护。实际50GiB容量夹具释放53,687,025,664字节，原包/静态库/人工历史不变；该证据不替代原生大项目G3/G4。

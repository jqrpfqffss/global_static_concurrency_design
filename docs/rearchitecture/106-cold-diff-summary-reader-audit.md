# 冷Diff摘要读取：下一段实现的边界

105号已实际解决跨批次复用和完整校验时的报告投影。**首次缓存缺失的摘要构建仍未改成有界读取**，不得把命中路径的通过说成整个Diff已完成。

## 真实剩余路径

`prepare_base → read_saved_json(facts/report) → EvidenceProvider.load → summarize`。`EvidenceProvider.load`本身明确是无界兼容恢复；分页UI接口不会自动让此路径省内存。`prepare_base`未命中时仍同时持有基准事实、报告、摘要索引。当前侧又在`cli.run`中以完整事实/报告调用同一个`summarize`，最后`compare`同时读取双版摘要。

实际需要逐项迁移的维度：

| 原方法 | 必须保留 | 有界实现边界（尚未实现） |
|---|---|---|
| `canonical_id` / `normalize` | 已有位置排除项、匿名类型规范化、build_root/CFG重映射、重命名/同名static身份 | 沿用原方法；不能增加规范化项消除差异 |
| `row_hashes` / `evidence_digest` | 外层明确无序集合的排序和重复数；内层参数/数组/执行步骤原顺序 | 每行完整散列，外存排序；不能把内层数组当集合 |
| `pointer_hashes` | 完整目标集合、target_set池和全部原行字段 | 按目标集合身份读取全部成员；外存去重/排序并输出与原JSON序列完全相同的摘要；不能按页分别摘要后拼接 |
| `summarize.functions/edges/return_edges` | 函数完整语义/宏摘要、返回类型、调用及返回值消费边；原排序/集合语义 | 外存函数与边索引，不加载完整函数体/无关大型证据；保留所有边 |
| `graph_for` | 每组访问函数的全部反向祖先、完整相关边、所有context roots/edges，原graph_id | SQLite索引反向闭包；只有加速缓存可限额，不能截断层数或边数 |
| 变量dimensions与私有隔离 | 声明、全部访问、执行域/NVIC、保护、覆盖、冲突、分类；原私有隔离全部前提 | 单对象完整读取/逐行散列；不以局部字段替代完整指纹，不新增SAFE豁免 |
| findings / 全局semantics / unknowns / TU | 原候选全部rules/conflicts/uncertainties，原8组全局关系、指针、未知、宏、includes、真实build_arguments | 逐关系有序游标，保留重复与所有原键；原TU非PARSED阻断不变 |
| `compare` / saved恢复 | 双版完整图和影响闭包、理由、risk_comparison、无法排除影响扩大、完整基准归档 | 摘要构建完成后再测此消费者；不能先声明整个Diff已经有界 |

## 后续验收顺序

1. 先定义只读原生关系游标/按对象读取器，不增加第二套workspace或新的风险判定；任何外存临时库都在当前任务独立目录，任务退出后仍保留失败诊断。
2. 每种原散列与外存方法用完整原方法对照：空/重复/异序、嵌套有序数组、匿名类型、同名static、build_root、重命名、CFG、pool/inline指针目标及损坏引用。仅最终hash相同还不够，独立生成的摘要全部字段也须相同。
3. 在真实原生小工程上对照全部摘要、影响对象、闭包和理由；`verify_against_full`仍为独立无缓存提取。再测试原始INAV完整库并记录Job/RSS/OS/临时/WAL/磁盘峰值；旧黄金只读，不能改旧state或引擎指纹来让其通过新扫描门禁。
4. 大库原方法若超预算，保留实际失败收据；可在明确更高受控预算取得完整对照，不能换用仅计数/分类统计作为标准。新原生生产者和整个Diff恢复都须另验。

当前不以新读路径替代这些原方法。本审计是后续实现合同，不是已完成代码或性能成绩；对应G1/G3/G4/G5保持待验。CMake未提交构建的输入等价性也仍是独立缺口，不能混进已通过的显式数据库工作字节场景。

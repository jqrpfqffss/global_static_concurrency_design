# CMake工作字节完整流程：准入合同

不能以删除CMake阻断替代实现。本段沿用已有WorkspaceResolver、working_snapshot、编译视图、InputSnapshot和原生发布链路，原固件及Git字节/目录/索引保持；所有构建、日志、生成文件、SDK副本在独立数据根。

Windows下以低完整性受监督进程执行实际CMake/Ninja/工具探测，只给新建私有输出目录低完整性标签，不改变原固件/程序权限。原源码命名空间使用不复位的内核变更信号检测ABA，外部配置/工具文件保持只读句柄，SDK/配置模块目录变动同样使任务失败。先以私有探测构建发现真实闭包，再在另一个新目录构建；配置输入、全部实际编译参数及生成的编译输入必须一致（仅已有规则可将实际构建路径映射作比较，不能改宏字面值）。

封存最终真实units/compilation、完整生成目录及配置/SDK后，precheck、扫描、独立无缓存核对、复核/恢复均使用该同一已校验准备结果，不再执行CMake。新能力记录单独版本并绑定有效analysis配置、所有准备数据SHA、原工程和受保护构建归属；缺少任何证据失败，不回退实时构建。

首次准入为Windows/Ninja、`compile_database: auto`及既有build_closure_only模式，普通CMake内建配置/生成及直接编译。未证明的项目自定义进程/生成命令、联网下载、try_run、跨域构建输入，以及不能绑定本轮生成物的显式ELF/MAP闭包继续明确拒绝，不修改分类或删掉输入来通过。通过范围需由真实工作字节/索引不变、生成头宏、独立全量、缓存、停止/改动/污染/损坏、保存后的复验以及真实GUI验收给出，不能把限定支持说成任意CMake脚本等价。

项目内GLOB源文件选择由完整原目录快照覆盖；外部GLOB和未证明的文件复制/解包模式继续拒绝。外部显式配置READ/STRINGS/哈希读取增加文件及父命名空间盘点，在最终构建前锁定并封存。不能证明归属的相对配置路径明确失败。项目依赖写权限条件的配置不能在只读模式下冒称等价。

阶段内校验不靠“文件看起来没有改”：先建立不复位的Windows目录变更监视和单文件只读句柄，再完整核对原件及副本；后续屏障检查变更信号和描述清单。正式发布者仍执行完整末次复验。该优化只用于新V3 CMake，旧V1/V2全量校验不变。复制/哈希/校验及低完整性命令循环均检查任务的安全停止标记。

CMake执行追踪通过继承的stderr管道由父进程写入独立Medium目录，不能放在被审计脚本可截断的Low构建目录。原始追踪全部保留并封存SHA，导入当前扫描的诊断审计；在配置完成、Ninja执行前审核实际命令。系统模块不能豁免任意进程调用。

开发日志保留：早期路径/所有权/工具链接错误，以及v6默认构建目录查找失败均未改标通过。v7因反复SDK校验问题在本次自有开发进程、无存活子进程时受控结束，记NOT_VERIFIED；后续必须在独立冻结副本上重验。v72内存回归不含本段CMake代码。所有完整验收结果以独立收据为准。

检查点复用单独接入任务恢复：只接受本数据根内FAILED/INTERRUPTED的原任务和逐字节相同配置，绑定原捕获计划的分析实现及有效配置摘要，完整复验V3原件/副本后复用原配置路径、生成目录及SDK，不再执行当前侧CMake。缺少完整计划才能重新固定；已有完整计划但损坏/实现变化/输入变化必须明确失败。新任务记录原任务、计划SHA、原配置SHA和视图SHA。旧显式数据库/复核/多核恢复入口保持原行为。本段需新的真实两TU中断、三TU恢复和保存后刷新验收，不能引用较早v73非中断结果代替。

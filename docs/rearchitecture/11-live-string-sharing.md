## 原始实施前合同（保留试验依据）

16GiB INAV恢复扫描在分类阶段真实失败，不能只优化发布器。当前FactParts对≤1024字符的不可变字符串使用131072项LRU；某字符串被LRU淘汰后，早期事实仍持有它，后续TU又可能分配同内容的第二个字符串。只减少物理对象，不改变字段、类型、顺序、次数、存储身份或任何分析策略。

保留原有LRU上界、长值旁路、原生dict/list、schema布局缓存与clear语义；在短值与字典键进入LRU前先用CPython的sys.intern找到仍存活的同值字符串。必须先intern再建LRU键，避免LRU键继续保留另一份重复参数。Python3.10文档说明intern字符串不是永久存活对象，事实/现有LRU仍持有它们的正常引用；解释器intern表的索引容量也计入实测，不把它当作零开销。目标Portable CPython3.10.9与开发3.10分别验证。

审核没有把字符串is比较当作扫描判定；字符串仍为原生str且不可变，仅对象复用发生变化。不得对可变访问/容器作同值合并，不改protected算法、不更换阈值。大型资源收益没有实测前保持NOT_VERIFIED；前一16GiB FAIL仍保留，不以小型字符串样本替代G3。

验证超过原LRU容量的真实两文件TU读取，完整JSON字节/类型/键与数组顺序相同，跨淘汰存活值共享、长文本旁路、clear后事实不变；回归现有TU/弱符号/解析失败和完整原生F030对照。可做同输入完整INAV TU归并诊断（明确非另一个原生G2），但最终仍须完整原生及全字段比较。

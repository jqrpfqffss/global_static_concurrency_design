# ADR：完整校验的会话页缓存

2026-11-03（北京时间），实现前决定。改变限EvidenceProvider.validate的只读SQLite连接，以及发布者全部提交之后的完整性检查阶段，使用64MiB页缓存建议值。元数据/分页连接和发布事务写入阶段继续使用原默认，不写数据库头，不改变schema、内容编码、数据集、遍历顺序、归一化、算法或任何完整性检查。不是向正在运行的v2验证器注入变更。

真实17.8GB原版辅助图上，独立诊断对同样的三个区间、各250000条完整有序边及child hash进行读取。两轮均750000行，完整有序tuple摘要相同c4583ad2...。控制为显式2048KiB，对照65536KiB，不冒充当前SQLite编译默认值精确等于控制值。

| 度量 | 控制2048KiB | 65536KiB |
|---|---:|---:|
| 逻辑读取调用 | 49196 | 17179 |
| 逻辑读取字节 | 201494576 | 70352944 |
| 观察RSS | 19386368 | 87814144 |
| 用户CPU | 4.875s | 4.53125s |
| 非独占耗时 | 21.047s | 4.734s |

[诊断收据](evidence/validation-cache-probe-v1.json)。只读源文件size/mtime不变；本诊断没有重新算全文件SHA，不将stat等同SHA。旧先新后、没有清OS缓存、共享HDD仍有其他任务，故不把耗时比外推为原生全扫描或完整校验加速；读取调用是本进程逻辑I/O，不冒充物理磁盘I/O。诊断有显式行数界限，只用于资源选择，生产校验仍完整读取所有节点/边/投影，无采样或数据上限。

[SQLite官方cache_size合同](https://www.sqlite.org/pragma.html#pragma_cache_size)说明负数按KiB计算建议页数，设置仅对当前连接有效，并按需分配。64MiB是页缓存目标而非整个验证进程硬内存上限；整体仍由现有Windows Job监督。保留mode=ro、query_only、trusted_schema=OFF、foreign_keys=ON、BEGIN一致读视图、完整integrity_check/foreign_key_check、所有类型/字节/哈希/引用和完整投影校验。没有关闭同步、WAL、检查或外键，没有写default_cache_size。

实施后需执行现有完整校验/恶意标量/schema专项、旧消费者、同输入F030全字段对照和新冻结回归；实际大型对照与标准完整包需用明确冻结的新验证器完整重做，结果完成前NOT_VERIFIED。v24/v25旧运行收据不能借给此后续变更。

首次仅只读连接变更的42项专项、43项旧消费者和真实F030完整facts/report差异0已通过；随后扩展到发布后检查这一相同只读阶段，必须重新验收，不能借首次收据。原发布同步/提交/独占原子链接策略保留。

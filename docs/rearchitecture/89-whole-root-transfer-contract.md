# 整套数据复制与恢复合同

用户[87号](87-functional-priority-execution.md)要求先必要功能，搬迁为第二项；此处不以复制文件数或“选择下次启动根”代替功能验收。本文件记录实际实现及接下来的验收合同，尚未把本项或H/G总门禁标为完成。

## 操作与安全边界

入口沿用“设置与验收状态 → 独立数据根”，下方新增“整套数据复制与恢复”区域，不增加导航或改变视觉体系。默认来源为当前Studio数据根；可明确选择另一完整Studio根恢复。目标为另一独立空目录。字段与动作固定为“整套复制的目标空目录”“检查整套复制计划”“开始完整复制并校验”。先显示实际文件数、字节数、两端路径、原根保留和重启生效说明。

新副本只在完整复制、逐文件SHA、数据库/证据/人工历史校验及活动配置重绑通过后，以同卷目录改名发布。跨盘时私有pending直接位于目标盘，避免跨卷rename伪原子。原根不删除、不重写静态库/原事件；系统运行互斥锁重新创建，活动锁文件不当用户证据复制。

| 状态 | 页面与动作 |
|---|---|
| 无计划/输入改变 | 只能检查，不能使用过期计划开始 |
| COPYING | 显示真实已校验文件/总文件、字节及已复用数；来源暂停其他操作 |
| VALIDATING | 明确“校验数据库与人工历史，所需时间未知”，不编整体百分比或ETA |
| COMPLETE | 新根已发布；显示目标及设置/重启方法，当前窗口仍使用原根 |
| FAILED/INTERRUPTED | 原根、pending和校验日志保留；仅有有效恢复记录时显示“重新校验并恢复复制” |
| 重启后 | 没有活进程拥有的任务标中断；重新核对来源后复用有效副本；发布后崩溃有独立恢复路径 |

## 实际实现

- 复用WorkspaceResolver和既有数据根边界/启动设置。API、启动初始化、扫描预算、清理任务、旧迁移、空间设置及存储写入均纳入跨进程静默窗口；不会因数据根忙而悄悄切到系统默认根。活动复制的查询接口仍能显示真实进度。
- 每个文件复制后SHA校验，提交记录fsync；中断只复用与源字节再次一致的已完成文件。源内容/文件集合/目录集合变化，目录冲突、链接、空间不足或校验失败均不发布。目录、未知文件和已提交WAL均保留。
- 已发布扫描重新验证完整有序事实/报告、证据对象、人工事件DAG、继承证明与AI收据；未发布的中断工作只保留，不冒充有效扫描。
- 只重绑活动profile中明确支持的执行路径；保存原完整profile和注释/未知字段，旧配置历史、任务原文、扫描及来源凭据不重写。旧CMake缓存和Git工作树无法靠字符串替换安全使用，完整移入新根保留区，由既有Resolver在新位置重新构建/固定版本。
- 从旧任务重试时，仅对经过原SHA验证的配置派生新的活动输出设置，原任务原文不改；仍重新验证输入，只复用有效TU缓存。活动配置/编译命令/实际依赖若继续引用旧数据根，明确阻断，不能依赖旧盘符静默完成。
- 搬迁控制日志位于来源根同级独立`.ecra-root-transfers`，私有pending位于目标盘；不会边复制来源边改来源清单。完成副本内保存完整文件校验收据与重绑/保留映射。它们是恢复控制与审计数据，不是新的事实权威库。

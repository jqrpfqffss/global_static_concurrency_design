# ADR：完整校验的有界读取缓存512MiB

2026-11-03：原固定环境大型完整校验仍在执行。在经过身份核对的旧验证子进程上观察到5548s时CPU1538.672s、进程read_bytes172202222681B、write_bytes3299099840B，IO优先级NORMAL、CPU NORMAL。**进程I/O计数不是物理盘流量，也不能单独证明瓶颈**；结合源码完整校验只有64MiB缓存，选择独立512MiB试验。原验证器/冻结代码不修改、不停止，保留对照。

`EvidenceProvider.validate`新增仅执行资源参数`cache_kib`，范围1024–524288KiB（拒绝bool/字符串），默认512MiB；元数据查询及普通分页预算不变。仍执行全部SQLite integrity_check、foreign_key_check、唯一权威根、全部节点/标量字节/顺序/哈希，以及全部重建投影逐行对照；临时投影仍在文件中且缓存8MiB。不删除或采样检查，不改schema/事务/证据/原标准化规则。新权威库写入仍64MiB，不将读取缓存冒充写入优化。

缓存是连接局部、按需分配的建议值，不是总内存限制；试验继续使用2GiB Job，规范化报告比较同时两连接的建议缓存合计1GiB。SQLite规则参见[官方cache_size说明](https://www.sqlite.org/pragma.html#pragma_cache_size)。真实大型内存/耗时必须另测，超出Job上限如实失败。

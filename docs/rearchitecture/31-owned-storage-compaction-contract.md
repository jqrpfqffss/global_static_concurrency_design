# ADR-022：新扫描空间整理与真实分配量（设计冻结，待接入）

## 已有实际依据

只在两个独立F030库副本调用Windows原生文件压缩：schema2逻辑10665984→物理7733248字节；另一个含完整新原生归档元数据的schema3库逻辑8957952→物理5963776字节。两个副本及各自原库的完整字节SHA保持，深层图/投影校验通过；两库provenance不同，不能跨库直接相减当作布局收益。FileStandardInfo、FileCompressionInfo和GetCompressedFileSize的实测值相符。此为小工程副本探针，尚未接入，不能外推大型G4或70%。[原始探针收据](evidence/ntfs-compression-probe-f030-v1.json)。

[Microsoft FSCTL_SET_COMPRESSION](https://learn.microsoft.com/windows/win32/api/winioctl/ni-winioctl-fsctl_set_compression)说明该操作同步执行、需要文件系统支持；目录设置只影响未来文件。本实现只处理明确列出的文件，不设置整个数据根或任何源码目录属性。[物理大小接口](https://learn.microsoft.com/en-us/windows/win32/fileio/obtaining-the-size-of-a-compressed-file)用于分配量，不把逻辑长度当作释放量。

## 数据与流水线合同

1. 默认自动，可选择关闭，操作设置独立于固件YAML。启动任务时固定策略，后续设置应用于下一次任务，不改变分析配置、哈希或判定规则。
2. 权威库仅在新建的私有pending文件、SQLite写连接已关闭后整理；可用时先VACUUM INTO新的同目录文件，完整性/外键和稳定根/节点ID核对后替换私有pending文件。原已发布归档不原地迁移/覆盖。文件写入仍使用FULL同步和独占原子发布。
3. 文件压缩必须在已验证的独立数据根内，不处理目录、链接、固件、程序安装目录。只处理新权威库、已完成Worker载荷和本任务真实TU key对应的缓存载荷；人工库、活动WAL/journal、原源码不进入计划。
4. 每个实际压缩文件前后完整SHA、逻辑长度与文件身份核对，记录实际文件分配量、状态及时间。能力不支持/超出官方单文件范围须显式SKIPPED，不能写成已压缩或虚造收益；实际I/O/完整性失败保留现场并阻止本次有效发布，旧有效扫描仍可使用。
5. 不删除或截断任何逻辑字节、缓存关系、人工事件或已引用对象。记录整理收据并进入审计索引；标准完整包仍是普通SQLite与ZIP64，未支持NTFS的电脑可解包正常读取。
6. 原生资源观察计入整理与临时文件峰值。全策略实测须包含权威库、Worker、缓存、WAL/临时、构建/工作树及完整标准归档，不能只报一个压缩文件或程序ZIP大小。

## 固定UI补充规格

导航、主布局、四卡、颜色和已有操作路径保持原合同。在“设置与验收状态”的现有独立数据根panel内追加“新扫描空间策略”：下拉“自动节省存储空间”/“保持普通文件”，按钮“保存空间策略”；说明“应用于下一次扫描，空间整理可能增加收尾时间”。读取/保存中禁重复提交，失败显示可恢复错误，成功必须读取回验。损坏设置保留原文备份；并发修改按revision拒绝，不静默覆盖。

在“数据与共享”原占用区域保留逐类行，使用中文名“扫描归档、工程与构建、共享缓存、工作与诊断、导出、设置”；每行同时显示逻辑字节与实际文件分配量。未测/不支持显示“未测量”，不能显示0。提示不包含文件系统元数据/其他程序占用；目录消失与读取失败标记采样不完整。复用现有字号/间距/token，不新增展示大屏、颜色或虚构ETA。

实际API为GET/POST `/api/storage/policy`，返回mode、revision、valid及必要修复文案；`/api/storage`追加分配量和测量状态。所有按钮接通这些真实业务操作后再构建前端。必须用真实Chrome验证保存/重开、任务固定策略、故障错误、实际压缩产物和中文路径；不是静态效果图。

## 验收门禁

当前NOT_VERIFIED。须验证新库全部typed关系/有序摘要、节点ID稳定、原输入不变、源/缓存完整SHA、旧归档/人工库不变、故障/路径/未知设置/冲突/非支持能力、真实API/UI及新Portable。需要新的完整冻结回归与同输入原生对照；不借v23收据证明此代码。大型70%目标由实际全策略收据决定，未达到继续FAIL。

# ECRA Studio 操作说明

后续源码的标准包/确认增量由浏览器直接下载，无需前端先构造完整Blob。链接只适用于单个已生成文件，15分钟内支持Range重试；链接过期后从软件重新发起下载，原扫描/人工记录仍保留。此变更已做源码实机浏览器验收，尚不在v27包中；[实际范围](49-native-browser-download.md)不包括多GiB INAV/第二台物理机。

当前为开发验收候选，完整重构发布门禁尚未通过。本说明描述当前源码功能；每个Portable包须有自己的源码清单和实包验收收据。历史包、测试结果与未通过项见[性能与验收记录](performance-and-acceptance.md)，不能用旧包收据证明新代码。

## 启动与数据位置

双击包内 `ECRA.cmd` 打开本地中文工作台。Portable内置Python 3.10.9、后端依赖和离线网页资源；使用端无需安装Node或系统Python。关闭启动窗口或按Ctrl+C停止服务，单独关闭浏览器标签不会结束服务。再次启动请使用新启动器打开的地址，旧会话地址会失效。

首次数据默认保存在 `%LOCALAPPDATA%/ECRAStudio/data`。当前源码可在“设置与验收状态 → 独立数据根”浏览或填写其他盘的空目录/已有Studio数据根，先检查再保存；关闭启动窗口后重新双击ECRA.cmd生效。当前窗口及扫描继续使用原目录，旧记录仍在原根；选择另一个根不搬迁数据，旧格式迁移请使用“数据与共享”。启动参数和ECRA_DATA_ROOT优先于GUI默认值。源码已实际通过启动器保存/重开/原人工事件保持流程，详见[目录验收](35-data-root-selection-acceptance.md)；该功能已在v25实包实际验收。完整数据根搬迁仍未实现。数据目录必须独立于固件和程序安装目录，升级软件时保留用户目录与启动偏好。

## 第一次使用

首页提供三个真实入口：

- **新建工程**：进入四步向导。
- **导入历史结果**：进入“数据与共享”，导入标准结果包，或检查旧结果归属后迁移。
- **打开示例**：导入本程序自带的真实STM32教学归档，查看实际风险、覆盖缺口、调用关系和代码，练习人工确认与分享。示例来自仓库代码的2个TU实际ARM对象编译及Clang分析，未链接固件、未做硬件验证，也不是用户工程。重复打开保留确认；已有结果时也能从首页“最近扫描与下一步”打开。

内置示例资产只读，打开后数据保存在当前独立数据根。资产缺失或摘要不符会明确拒绝导入，已有结果仍保留。

## 接入工程与扫描

1. **选择工程**：填写名称和固件绝对路径，或使用“选择固件目录”。目录浏览只读当前层元数据，不上传源码、不创建文件夹；取消/ESC保留原值。
2. **确认构建**：选择外置CMake/Ninja、目标、Toolchain、构建变体，或已有真实编译数据库。宏和目标以实际命令为准。标准头文件可选引擎默认/明确开启/关闭；默认保持原行为：CMake开启、编译数据库关闭。开启时探测实际编译器，编译器不可用会报错。
3. **分析范围**：逐行填写纳入/排除目录，或从工程根内的目录树选择；“.”表示全部目录。排除仅影响变量清单，仍参与调用恢复。可以编辑main/ISR/任务等入口的ID、类型和逐行函数，分页访问全部入口。高级正则、优先级和未知字段保留；移除入口会移除该入口整段配置。Git版本支持分页/搜索真实分支与标签、输入ref、查看HEAD和未提交覆盖范围；扫描时重新固定输入。
4. **检查与保存**：先检查配置路径并保存独立配置，再选择“检查真实构建”。等待实际构建和全部TU编译输入检查通过，查看目标/变体、工具版本、独立路径及逐TU全部原始/Clang参数后，“开始此配置扫描”才启用。修改或恢复配置后须重新保存并检查。检查失败会显示工具路径/编译错误及修复方法，旧结果保留。历史检查记录可查看，不能直接授予新编辑会话的启动许可。此功能已在当前源码实现并实测；v15封存包不包含它，新Portable须另验。高级YAML原文可完整编辑；返回普通字段后只同步实际改动，下一步可恢复同步前原文。共享引用无法证明局部编辑时明确保留原文。

配置保存后可从首页“按此配置重新扫描”启动。任务中心“检查并扫描”也会先检查再提取事实。检查本身不是静态安全结论。任务中心提供真实阶段、TU计数、资源采样和日志；没有可证明分母或剩余量时不显示假ETA。停止后保留已校验TU缓存，再次开始须重新校验输入；全局分析从入口重做，不是任意指令处续跑。上一次有效结果独立保留。

正式流程拒绝在固件/安装目录内输出，并拒绝尚未完整隔离的未提交输入。完整进程写保护、只读挂载和dirty生产隔离仍未完成验收，不能据此宣称H2已通过。

## 查看证据与人工确认

首页四张卡分别表示静态疑似、无法判断、当前构建已证明安全和人工待确认，点击按同一口径下钻。容器、范围外对象和未观察到的风险不能冒充已证明安全。

变量工作台按服务端筛选/排序/分页读取数据。左侧可按名称、文件或规范身份查询；筛选区和列表分别滚动。右侧按“时序与访问、调用与保护、归档源码、人工历史”查看，完整证据可继续展开、取段或翻页。未归档的源码明确显示缺失，不从当前工程冒充补齐。桌面双栏按剩余视口分配空间，人工填写区与决定动作留在栏内；长内容可在对应区域滚动。

填写声明确认者及依据，选择确认有风险、确认无风险或暂无法确认。确认无风险必须有依据；处理状态独立于判定。提交成功后才显示已保存。撤销必须说明理由并新增审计事件，原操作保留。确认者是未经认证的声明，不是登录身份。

关闭软件重开后，已提交确认和位置保留，可“继续上次位置”。同工程/profile新扫描保留旧确认的来源与完整事件；证据变化或无法证明相同时显示“需重新确认”。当前采用保守全库指纹，可能增加复核量，不能仅按名称继承旧安全结论。

## OpenCode、共享与旧结果

静态扫描默认不调用模型。OpenCode页面可查看真实队列、技术状态与原始收据，并发起全部候选或技术失败项的复核；需要有效的外部工具/模型配置、本机恢复检查点和原源码。模型配置的普通表单尚未齐备。TECH_FAILED不会改变静态分类；导入包的归档查看不等于可以重新证明源码。

“数据与共享”支持标准完整 `.ecra-report` 和人工确认增量 `.ecra-review-delta`。完整包可在没有原固件的电脑查看全部已归档证据并继续确认，不能在缺源码时进行原生重扫。重复导入幂等；并行确认分歧会保留双方事件并显示冲突，核对历史、填写新依据后显式解决，不按最后写入覆盖。包可能包含源码和备注，请按团队规则分享。

旧 `.ecra` 或工具workspace须先检查旧目录与原记录的工程归属，再只读迁移；原文件保留。缺少完整facts.json/报告、存在活锁/WAL或归属不符时明确失败。未经合同验证的旧决定不会自动成为本轮安全结论。不要删除旧结果、随意改名成新包或用当前源码补造旧证据；巨型/双来源合并与缺证据专用降级Viewer尚未全部完成。

## 空间管理与验收范围

先生成空间预览，核对路径后确认隔离；可恢复，永久释放还需单独确认。只处理无引用对象和受控可重建缓存，保留有效扫描、人工历史、构建和导出。引用或内容变化、占用与锁冲突时停止并保留现场。界面文件占用是逻辑字节采样，实际物理释放量可能不同。

大型原生full/Diff全字段对照、32GB实机、磁盘70%目标、全部故障矩阵、干净离线机、物理双电脑、系统高DPI及独立工程师盲测尚未全部通过。具体代码、测试、PASS/FAIL/NOT_VERIFIED与每个包的独立收据见[需求追踪](01-requirements-traceability.md)及[性能与验收记录](performance-and-acceptance.md)。真实浏览器自动化不是工程师盲测或硬件验证。

开发复现使用 `py -3.10 -B -m unittest discover -s tests -v`；不能把发现0项的退出0当作全套通过。前端源码构建需要开发端Node，最终使用端不需要。构建包须使用全新输出目录；不含.git的冻结源通过旁置逐文件SHA清单验证，包内保留SOURCE-SNAPSHOT.json，实际交付仍须独立实包复验。

源码新增：旧目录缺完整事实/报告/身份时，可显式勾选“证据不全时只保存原文件”，预览缺失项后迁移为UNVERIFIED原件归档。全部现存字节保留并可标准包往返；此时不恢复可信变量，不提供人工确认/复核，不把零对象当零风险。已知归属冲突、活动WAL和已有检查点哈希错误仍拒绝。此功能和深TEMP短路径修复需要后续新包，v16不包含降级Viewer且实测深CMake失败，详见[阶段记录](19-legacy-and-portable-stage-20261102.md)。
# 当前源码新增：沿用确认与整套数据复制

这两项是当前分支源码及已构建前端的能力；此前封口Portable v37不包含本次新增代码，新Portable不能在未重新验证前宣称完成。

重新扫描后，只有完整输入和全部事实都能证明未变，人工确认区才显示“沿用”及原确认人、时间、扫描来源。原事件仍在“人工历史”，不会冒充新确认。填写理由可“撤销上次确认”，刷新/重新扫描后仍需重核；变化或缺证明显示“需重新确认”。不同来源的并行确认需核对并显式解决冲突。相同来源含不同历史快照时不会覆盖原记录。

搬迁或恢复完整Studio数据：打开“设置与验收状态 → 独立数据根 → 整套数据复制与恢复”，选择另一独立空目标，先检查实际路径、文件数和字节数，再“开始完整复制并校验”。恢复另一已有Studio根时勾选来源选项。成功后在上方选择新目标并保存，关闭软件重新启动；当前窗口仍使用原根，显式启动参数/环境变量按页面提示优先。整个过程保留原目录。

复制失败会保留原根和私有pending。存在有效校验日志时使用“重新校验并恢复复制”；来源变化则重新检查新计划，不强行续用旧证明。新根会重新建立活动构建/Git工作树；旧运行目录完整保留。若编译输入还指向旧盘符，软件会阻断并给出重新检查/导出编译数据库的动作，不静默读取旧目录。验收范围和限制见[90号](90-whole-root-transfer-acceptance.md)。


复核现有扫描：从OpenCode复核页选择当前工程配置，可重新复核全部疑似/未知或仅技术失败。进入任务日志后可安全停止；重试先重验原输入，再按原模式执行。已处理计数包含技术失败，任务结束不等于安全。收据和历史保留，Packet可分段完整查看。原生入口现不恢复整个事实图；大工程联合资源及使用限制见[97号](97-native-review-packet-acceptance.md)。封存Portable v37不含这些后续功能。

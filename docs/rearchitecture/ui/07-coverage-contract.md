# 覆盖与诊断实施规格

继承任务书7.7与固定九导航，不变更静态算法或重新推断覆盖。页面从只显示原始树改为：状态与TU真实计数→四个分组→原始完整索引。分组为“变量覆盖阻断”“解析/别名/硬件记录”“编译单元”“构建与范围”。采用已有panel、tag、分页、EvidenceNode、中文颜色和字号，不添加虚构覆盖百分比或安全横幅。

变量阻断直接读取report.coverage.blocker_fanout中的完整symbol_ids/relevance_proofs，展示引擎原关联计数及列表数；不在UI扩大或缩小影响。原始缺口按facts.unknowns.kind原值分组；直接symbol_id关联与引擎传播关联明确区分。缺少关联不代表零影响。每个类型有中文解释和基于真实输入的修复方向，未知类型显示原值及完整证据，不能映射SAFE。

编译单元按PARSED/PARTIAL/FAILED原值分别计数，不用含PARTIAL的100%代替完整覆盖。全部TU均可分页查看，含成功但无关联对象TU。关联对象数只依据变量保留的translation_units列表，含容器/非存储；来源缺失或同名TU有多个编译变体时，不提供未经证明的“零变量”筛选。编译参数、头文件、原始诊断按需读取，不丢弃零变量TU。构建页列出原构建闭包、排除/未列出文件与头、编译器/宏来源；仍提示目录排除与变量清单的关系，不能把HAL调用恢复一并删掉。

所有行由服务器分页，默认50/最大200；接口不调用EvidenceProvider.load。原始长文本以node引用继续读取，列表不得悄悄截断诊断。不存在的集合显示“未归档/无法判断”，不显示0风险；非对象/未知原始条目数量另行提示并保留完整索引。加载、空、未知、失败、归档模式均需显示状态。

TU状态类型在摘要最多50种，常见PARSED/PARTIAL/FAILED优先，另返回真实类型总量；超出时明确提示，全部TU和原始状态不丢。编译单元详情分别提供原始命令、实际解析参数、诊断、头文件的完整证据入口，并复用归档SourceViewer，不能读取当前源码填补历史。成功但零关联对象的TU仍可查看。

从实际关联canonical身份打开共用变量工作台；返回覆盖页恢复分组、筛选、页码与当前证据。状态写入独立reviews.db的coverage位置，不改静态库。加载失败显示错误并保留原始数据，不能将上一扫描的统计冒充当前扫描。验收必须实际查询、筛选、翻页、打开对象、返回/重开，并断言scan.db SHA不变；脚本及收据完成后登记，文档本身不是通过声明。

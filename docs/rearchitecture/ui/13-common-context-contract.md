# 常用入口与编译器头文件配置合同（编码前冻结）

继承工程配置的四步、左右栏、导航和设计令牌。只补全第2步的编译器头文件选项及第3步的main/ISR/任务入口，不更换页面结构。高级完整YAML继续作为配置权威，不自动推断或改变中断、抢占、RTOS、DMA语义。

- 第2步“编译器标准头文件”显示按引擎默认/明确开启/明确关闭。默认含义如实显示：CMake开启、编译数据库关闭。保持缺省键缺省；仅用户明确选择才写入或移除 `analysis.auto_system_includes`，不借UI调整原扫描策略。
- 第3步在目录范围与Git版本之间增加“执行入口”。每行可编辑入口ID、现有引擎支持的类型及逐行函数名，能添加/移除入口。初次配置保留原来的main入口；读取旧配置时采用实际入口，不补造默认入口。函数名保留空格、逗号和重复项，不做静默去重/排序。每页8行，可翻到全部入口。
- 普通编辑只改该行的ID、kind、functions；patterns/regex/优先级/使能和未知字段、引号/注释随原入口保留。原行的隐藏身份只用于定位；不写进YAML，不以编辑后的ID误配其他行。已有行不提供重排。移除明确表示移除整段入口（包括高级字段），页面提示此范围；同步前完整原文进入已有不可变备份，下一步可恢复。
- 含共享入口列表/共享入口映射/共享functions列表、合并键、缺失/重复身份、未知类型或普通逐行表单不能表达的函数值时，仅入口编辑禁用并显示原因；其他普通字段仍可编辑，高级原文保留。API不能绕过该拒绝。禁止猜测别名应否同步到其他高级字段。
- 变更完成后，用现有引擎解释器对完整类型、字典/列表顺序及别名拓扑复验，只接受“原配置应用所选字段变化”的结果。修改ID/移除入口不自动改写高级并发关系；环境检查会用原配置校验器报告悬空引用，检查保存后才可启动。
- 高级原文→返回→普通修改→同步→备份/恢复→检查保存→重开流程继续有效。读取无变化时不新增缺省键、不写回原文。目录空字符串无法无损往返时明确拒绝，不在前后退过程中悄悄丢弃。

验收范围：真实配置的高级入口字段/注释/CRLF/别名与重复函数保留，ID重命名/增删/非法身份及共享引用拒绝，显式头文件设置和缺省行为；真实Chrome普通操作、翻页、往返、备份恢复、保存重开、1366/1600动作可见及固件不变。仍需其他U02场景、系统DPI、实际工程师UAT；本轮不宣布U02/G7全通过。

# 真实构建预检查：U02/U05 实施前交互合同

沿用四步向导、现有设计 token 和任务监督器，不新增一级导航。补齐第4步缺少的真实编译检查与执行计划，不将路径存在视为编译参数通过。

第4步顺序：高级配置/路径校验 → 保存独立配置 → 检查真实构建 → 查看计划 → 开始此配置扫描。允许保存暂不可运行的配置；配置、profile修订变化或重新检查立即清除旧的启动许可。检查运行时显示真实任务、日志与停止入口；切换页面不取消后台检查。检查成功才启用向导扫描按钮。

计划显示固件/实际分析根、目标/变体、编译数据库、独立构建与数据位置、TU总数、逐TU真实工作目录/原始编译命令/规范化Clang参数、实际工具路径及版本、输入校验状态。命令按TU分页、逐项展开，不能静默只显示前若干项。无结果、检查中、成功、失败、配置变化各有独立中文状态。失败保留诊断，允许修正配置后重试。

预检查由原TaskManager创建独立受监督子进程，共用数据根预算。复用WorkspaceResolver、Git pin/prepare_current、compilation.prepare和dependency_results/InputSnapshot，不另写编译参数规则。CMake按现有外置构建合同实际配置并构建；数据库模式读取实际命令、运行需要的编译器版本检查并使用实际Clang参数验证完整依赖闭包。仅探测所需工具，OpenCode缺失不阻止静态扫描。全量非Git工程不要求Git。

任何扫描任务在Clang事实提取/静态发布前执行真实预检查，GUI许可不是服务端信任凭据。首页“按此配置重新扫描”和任务中心“检查并扫描”自动完成检查后进入扫描；新建向导先展示计划。失败只产生外部work内诊断，不发布scan.db、不改变上次有效指针或人工历史。预检查不是静态安全结论；正式扫描继续原有构建/输入/覆盖门禁，不能借此跳过未知/部分覆盖。

只读适用性仍受现有正式构建合同约束；此项不冒称已集成生产Windows写保护沙箱。H2剩余门禁和物理只读卷测试继续待验。

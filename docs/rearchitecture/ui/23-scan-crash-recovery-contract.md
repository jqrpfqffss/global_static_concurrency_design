# 扫描中断与程序重启验收合同

本轮不改布局、按钮、静态分析或恢复语义。使用冻结Portable的真实服务、Chrome和已获准F030输入，在新的独立数据根内验收U08/G5。故障只作用于本验收创建、命令行及创建时间再次核对的进程，不终止其他扫描/程序。

| 状态/动作 | 必须观察到的结果 | 证据 |
|---|---|---|
| 首轮真实扫描并添加暂无法确认 | 有效静态库、原始人工事件和最新指针存在；确认不是安全证明 | SQLite与GUI截图 |
| 第二轮真实原生阶段生产进程异常退出 | 当前任务FAILED，无有效发布；原有效库/人工事件/最新指针不变；GUI不显示该失败任务可打开扫描结果 | 进程身份、原生目录、实际任务页 |
| 从失败任务重试 | 重新进行真实输入检查，只复用完全匹配TU缓存，完整原生扫描完成；原有效静态库及事件不变 | 缓存命中、完整库校验、GUI |
| 下一轮原生阶段服务进程异常退出 | Job内生产进程与后代结束；数据根和原输入保留 | 进程创建时间/命令行及退出检查 |
| 重开同数据根 | 原任务INTERRUPTED，最后有效扫描和全部旧人工记录可查看；不把中断当作安全扫描 | 新会话真实Chrome及数据库 |
| 再次重试 | 内容校验后的TU缓存被复用，新的有效扫描可查看，旧库/事件仍保持 | 原生检查和GUI |

控制器不模拟API、页面、任务状态或工具退出；不修改真实固件，原输入前后逐文件SHA核对。为绑定测试数据根，只在私有配置副本修改输出位置；黄金DB使用原外部工具链时，必须显式提供`--allow-external-toolchain`，沿原生产门禁允许已获准的实际工具链，不替换编译器、数据库、宏、上下文或判定规则。自动化确认显式声明其测试用途，决定只能暂无法确认。

该合同不包含断电、系统重启、磁盘满、全部Worker故障类或大工程恢复，不能替代完整G5；真实Windows程序异常退出也不等于物理32GB或UAT。每次必须创建全新诊断目录，所有失败与未发布现场保留，不能清空旧目录重跑成PASS。

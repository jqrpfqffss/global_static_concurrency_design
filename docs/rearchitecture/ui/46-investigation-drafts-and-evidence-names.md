# 调查草稿与证据名称交互补充（v80）

2026-11-07，先在实际 v79 Portable、空数据根、真实 STM32F030 完整包中复现，再冻结本补充。遵守 01/04/16 的现有导航、分栏与证据次序；不重绘工作台。

## 实际问题

- 从概览进入 `systicks`，填写调查依据、选择“待验证”，Esc 返回列表后重新选择：依据变为空、处理状态恢复待修复，无提示。原始失败与截图保存在外部 `user-journey-v80`，不得用修复结果覆盖。
- 并发关系展示 `auto:SysTick_Handler:bacec779`、`c:@F@SysTick_Handler`。同一归档的函数定义已有 `SysTick_Handler()`；工程师应先读实际名称，再按需核对身份。

## 冻结行为

1. 未提交的依据及处理状态按扫描和规范变量身份独立暂存；同名 static 不混淆。切换对象、Esc、筛选和页面导航不丢失草稿，也不生成确认事件。界面明确提示草稿仅在当前窗口保留；刷新/关闭存在任意草稿时触发浏览器离开提醒。此阶段不声称草稿已落盘或可跨进程恢复。
2. 保存确认成功立即清除已提交草稿；后续统计刷新失败不能让用户误以为确认未写入。请求失败保留草稿。若重新进入时原证据指纹或确认分支已变化，保留文字并提示重新核对，仍由后端执行原有指纹/分支校验。
3. 切换对象时清空旧的证据和人工状态；当前读取未完成或失败时禁止确认。迟到响应不得串到其他对象。用户可重新点击对象重试。
4. 关系卡及访问行优先显示归档中的函数全名；按确切函数身份查询，不解析字符串猜测名称，不合并同名函数。上下文按归档 `id` 匹配，显示记录的种类和物理域；缺失或未知仍显示待核实。原始身份始终可见，完整原证据继续可展开。
5. 名称查询逐页、有界，缓存最多 128 个查询结果，不整库载入。名称查询失败不隐藏原始参与者或代码跳转，并提供重试。
6. 不更改扫描、冲突判定、人工事件协议、归档数据或完整包格式。自动化声明明确标识；不代表人工盲测或真实风险结论。
7. 后续真实损坏文件交接复现：原提示只有“操作未完成，原归档保留；诊断编号”，缺少用户下一步。导入请求失败时在原错误与编号前补充检查文件完整性、数据盘可用空间及重新选择文件的指引；确认增量还须核对归档归属。不推断具体损坏原因，不把成功提交后的页面刷新失败说成导入失败。
8. 从四步向导实际扫描 F030 后，覆盖页将引擎已知的 `EXECUTION_CONTEXT_UNRESOLVED` 显示为未识别缺口。补齐“执行上下文未恢复”和核对入口/调用者/回调的建议；原类型与原始记录保留。关系卡中已有入口种类使用中文名称，新增或未知种类保留原代码，不能据此推导抢占或保护结论。最终包含本项的小修订候选为 v81，v80 中间源/包不覆盖。

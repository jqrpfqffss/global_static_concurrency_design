# ECRA Studio 产品规格（冻结 v1）

来源：任务书 §7–12；继承 `docs/assets/desktop-proposal/01–04` 的构图。验收以真实 API/数据库/浏览器三项为准。

角色：操作工程师接入并重复扫描；排查工程师定位变量/交错/保护；负责人查看覆盖及处理闭环；离线审核者仅持结果包查看并确认。每个角色均通过项目身份、profile、scan、有效性进入同一工作台。

导航顺序固定：项目概览、工程配置、扫描任务、变量与风险、覆盖与诊断、OpenCode 复核、人工确认、历史与对比、数据与共享；设置在底部。

概览优先回答工程/构建/版本/有效性/待办/继续位置。四卡固定为静态疑似、无法判断、当前构建已证明安全、人工待确认；卡片参数与实际查询共用口径。容器/范围外/非存储单列分母。左65%为优先处理对象，右35%覆盖/失败/AI提示，下面历史与下一步。不添加虚构统计图。

向导固定四步：工程目录与名称 → 真实构建/工具链/变体 → 范围/入口/Diff → 环境检查/计划/外部路径/启动。后退保留值。初次仅工程、导入、示例；高级 YAML 不覆盖未知字段/注释，必要时另存。已登记项目日常一键重扫。

扫描中心：身份/阶段/TU计数，资源实测和日志，稳定可见的开始/安全停止/检查点恢复/重试（实现并验证才出现）。无分母写“剩余量未知”；旧有效结果始终可打开。

变量工作台与人工工作台共用左列表38%+右证据62%，服务端分页。顺序：完整身份与分层一句话结论 → 推断交错及条件 → 访问 → 完整可继续调用边 → 归档代码 → NVIC/保护/初始化/别名/覆盖 → AI → 人工与历史。任何静态推断标明非硬件实测。未知枚举显示中文未知状态及原值。

覆盖页按根因与真实 TU/对象下钻。AI页保留原始/中文执行状态，不把 DONE 当安全，不强制启用。人工页分组计数、继续上次、三种决策、独立处理状态，确认无风险需依据，撤销新增事件。冲突查看双方来源后解决。

历史按工程/配置/版本/模式/状态筛选。共享展示标准包/增量/历史迁移的阶段、来源和能力限制。数据空间用真实分类占用；回收先计划再确认，移除项目不删除固件。

功能未实现时显示具体能力边界与原因，不显示可点主按钮或假成功。生产页面不内置演示风险、变量、统计或模拟扫描进度。

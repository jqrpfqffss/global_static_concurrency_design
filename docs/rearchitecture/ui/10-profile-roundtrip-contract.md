# 四步向导配置同步合同（实施前冻结）

继承既定四步、工程配置页及保存/启动动作，不新增导航或统计页。解决当前“高级YAML保留但表单修改不生效”的实际缺陷。分析配置仍以保存的完整YAML为权威，不能把未应用的表单值展示成已生效参数。

1. 从第4步返回时，依据当前完整YAML填充可表达的普通字段；不能用最初表单值覆盖用户后来写入的高级设置。普通字段只有用户实际修改的部分可以更新YAML。
2. 同步采用保留注释/引号/未知映射的round-trip编辑；写回后用现有PyYAML解释器复读，和“原配置仅应用受控字段变更”的预期作完整类型敏感比较。出现非预期变化直接拒绝，原文仍在。
3. 每次同步先在独立settings/profile-drafts保存完整原始UTF-8原文，返回可见的备份/恢复入口。切换CMake/数据库模式若移除旧构建分支，必须明确说明，并可恢复包含全部高级字段的原文；不能静默丢弃未知选项。
4. 目录集合改为每行一个目录，保留空格和逗号；只有CMake显示可实际生效的构建变体，数据库模式说明宏/编译参数以真实数据库为准。已有高级上下文/保护/Diff等未编辑字段保持原样。
5. 同步、环境检查和保存期间防止并发选择覆盖；失败可回到高级原文修复。修改后检查状态和已保存启动资格失效，重新检查保存后才能真实扫描。恢复原文也须重新检查保存。
6. 不修改原工程、全局config/semantics.yaml或编译数据库，不执行配置中的任意代码。YAML不支持/歧义/别名影响无法证明只限受控字段时，明确失败并保留原文，禁止猜测后继续。

实机修正：首版1366×768截图发现检查明细与原文备份将主操作挤到首屏以下，该版不满足U22。仍保留原双栏/四步，将左栏表单内容限制在可滚动区域，底部前进/后退/保存/启动操作固定留在栏内；路径检查明细默认折叠，缺工具时展开。不删除任何检查内容。增加实际按钮坐标断言，不能仅靠无水平滚动判断可用。系统DPI仍待验。

验收：注释/未知字段/引号/类型/逗号路径/锚点与合并键、构建模式切换备份、原文恢复、非法输入无覆盖，以及真实浏览器高级编辑→后退→修改→前进→检查保存→重开。使用已获准F030验证真实功能；不计为额外G2工程，U02完整场景仍以实际覆盖结果更新。

实现依据：[ruamel.yaml round-trip示例](https://yaml.dev/doc/ruamel.yaml/example/)。保留风格能力必须由本项目测试证明，不能将第三方功能描述当成验收。

# 已有多核结果合并：固定交互合同

本流程属于任务§1/6/7.4已有多核能力的普通用户入口。沿用“数据与共享”及既有任务中心/证据工作台，不新增一级导航，不更换布局、色彩、风险标签或结果协议。

入口为“数据与共享”页顶部次要按钮“合并已有多核结果”，展开并滚动到原页内合并区，键盘焦点进入该区；不新建路由/多级弹窗。默认收起。流程分三步：①选择核心的确切扫描批次、唯一别名及原生文件选择器上传的对应ARM ELF32；②按真实链接脚本填写共享RAM和实际资源预算；③核对每个输入的扫描/profile/core及区域后提交。返回保留输入，修改输入作废计划；每步只有一个强主操作。

实际v1完整页截图证明同时堆叠输入、共享区域和哈希核对会使主要动作过深，故按任务§7.4/7.11分步骤原则调整，不改变既有信息架构和视觉token。1366×768时须验证当前步骤主操作在滚动到合并区后可见；原始SHA放可展开的来源详情，扫描/core身份仍直接显示。默认两个输入，可明确添加/移除；区域默认空白，不猜测。配置从所选扫描的原始、带哈希字节恢复，不要求修改YAML或猜测当前profile是否仍对应旧扫描。

| 状态 | 必须显示 / 操作 | 后端与持久化合同 |
|---|---|---|
| EMPTY | 无可选归档时说明先扫描/导入；没有选择输入时禁止检查 | 不产生派生结果 |
| SELECTING | 核心别名、扫描批次、所选ELF名称、共享区域与实际资源预算 | 上传流式写独立work目录，返回不可猜测ID和完整SHA；不读取浏览器未选中的本机路径 |
| UPLOADING/CHECKING | 真实进行中与剩余量未知；不能显示假百分比 | 文件类型、元数据、原始配置、工程归属和输入选择校验失败明确反馈；原数据不改 |
| FIXED | 显示每个核心的扫描/profile、归档core与配置SHA；显示后续完整校验能力边界 | 固定计划含完整binding、扫描/清单/ELF预期SHA及归档配置字节；改输入即作废当前计划 |
| RUNNING | 真实任务中心显示“多核派生合并”、未知分母、进程树资源/日志、安全停止 | 复用TaskManager/OwnedProcess/共享预算；worker完整校验选择后才分析；不以CLI成功码单独判断发布 |
| FAILED/INTERRUPTED | 中文原因、原结果保留；“重新校验固定输入并重试合并” | 重试从固定输入校验和组合入口重新执行，不显示TU检查点恢复；无有效manifest不展示新有效结果 |
| PUBLISHED | 从任务打开既有变量证据/人工确认/完整包流程 | INCOMPLETE和链接地址派生说明保持；不更新任一单核心latest指针，不产生旧HTML/事实JSON |

同一批次被选择为多个别名时明确显示重复输入提示，不能当作真实多核工程证明。初期仅支持相同工程身份与原始根的已归档配置，不跨不同固件工程猜测身份。缺原始配置或摘要不符时拒绝；不使用有损文本预览替代原始配置。

输入扫描的原人工记录保留在各自归档；派生对象根据合并后证据独立确认，不能自动套用原SAFE。任务中心显示真实派生阶段及资源，不以0/0 TU暗示执行了新原生扫描；停止/重试继续使用固定输入的重检与组合语义。

此合同不是验收通过声明。必须用真实API与数据库断言验证输入固定、陈旧latest、预检后变化、共享预算、失败/重试、人工记录与标准包；获准F030别名的实际操作只证明执行链和发布，不填补用户延期的真实双核G2。截图须使用真实运行页面，覆盖1366×768、失败和完成状态；工程师UAT仍待验。

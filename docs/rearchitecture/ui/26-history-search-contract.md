# 历史检索与逐归档操作合同

2026-11-02，实施前冻结。继承任务书§7.10、现有九导航、浅色面板、蓝色单一主动作与8px间距，不另造首页。

| 区域 | 冻结交互 |
|---|---|
| 页首 | 历史与对比；说明归档身份不等于当前源码有效，未观察到不等于修复。 |
| 检索面板 | 工程名称/ID、配置/目标/变体、核心声明、Git ref/提交均为字面包含；模式、发布状态精确筛选；UTC起止日期包含两端。查询/清空；不逐键触发。 |
| 列表 | 最新有日期记录在前，未记录日期在末；每页20条，总数/已显示范围、上一页/下一页。归档工程、配置、核心、Git比较方向/提交、状态、覆盖、日期和批次均可换行。 |
| 逐条动作 | 打开结果、继续人工确认、导出标准完整包、导出人工确认增量，全部绑定该行scan_id，不能误操作当前顶栏的另一批次。缺证据旧原件禁止人工确认/增量。 |
| 对比边界 | 已归档Diff显示真实固定方向；跨历史批次完整语义对比尚未实现，不呈现假按钮。 |
| 位置 | 筛选与页码保存在当前标签页的sessionStorage，按数据根隔离；返回/刷新保留，结果减少时回到最后有效页。 |

| 状态 | 显示与操作 |
|---|---|
| LOADING | 明确正在读取；检索/逐条操作暂禁，旧页不冒充新查询结果。 |
| EMPTY | 尚无归档；或没有匹配项并建议调整筛选，两者区分。 |
| VALID/PARTIAL/OFFLINE_ARCHIVE | 原始状态配中文说明，静态覆盖和人工/AI结论不混同。 |
| FAILED/PERMISSION_ERROR | 损坏单条留在列表并显示诊断，禁用打开/导出；查询整体失败显示错误和重试，不能显示零风险。 |
| 未记录/未知枚举 | 明示未记录或保留原枚举，不从目录/芯片猜核心或补造日期。 |

服务端`GET /api/history`经原Host/Origin/session边界；页长1–100。遍历扫描目录时跳过未发布任务，链接路径拒绝。只读EvidenceProvider读取身份；完整事实禁止load。逐条元数据写入独立数据根新建临时SQLite主表，以主键顺序分页，避免在Python汇集全部扫描/事实；原库、人工事件与固件不写入。查询临时表不成为权威库或安全证明。日期来自本机发布completed_at或归档generated_at，不能拿导入时间/文件mtime冒充扫描时间。发布者状态须与当前静态身份绑定。

验收：真实归档组合筛选/日期/分页/损坏/未发布/重开保持、按行导出再导入核对身份和人工事件、禁全图load、原库SHA不变；真实Chrome截图覆盖1600×900/1366×768。此子范围不替代U19第二物理机、U21大工程迁移、原生Diff/G1或G7全场景。

实施后视觉审查（v2实际截图）：20个完整身份条目让分页落到长页面底部，不符合日常定位效率。按原布局修正为工程/配置常用检索常驻，其余筛选采用既有折叠区，已保存非空高级筛选重开时自动展开；匹配数和分页位于列表上方，列表在桌面可键盘聚焦、独立滚动。1366下分页必须在视口内；不截断或删去行内身份/证据。此调整不增加导航或另选视觉风格。v2操作收据保留，调整后必须独立重验。

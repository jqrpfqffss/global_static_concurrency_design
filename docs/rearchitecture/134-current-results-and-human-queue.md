本轮从 `optimize_ccc` 的 `8e6cac04bb57053b43c49636096e862a339af722` 开始，执行前工作区干净。按用户最新要求修复结果展示和人工待办，不修改静态算法、OpenCode 输出合同、严格对照规则或人工事件协议。

## 问题与处理规则

原实现将“没有人工签署”直接解释为“待人工确认”，所以静态安全、OpenCode 安全、容器对象也进入待办。概览与变量列表主要读取原静态分类，复核页读取另一套 AI 账本；复核完成后没有统一刷新。人工页还会沿用变量页的筛选，导致待办数量与实际列表不一致。

现在所有相关页面使用一个只读的当前结论投影，原始证据仍独立保存：

| 当前分析结果 | 是否属于人工确认范围 | 未签署时的展示 |
| --- | --- | --- |
| 确认并发风险 | 是 | 待确认 |
| 疑似并发风险 | 是 | 待确认 |
| 无法判断 | 是 | 待确认 |
| 静态安全、OpenCode 条件下安全或静态误报 | 否 | 无需人工确认 |
| 无需复核的共享对象、容器、未进入构建、非存储对象 | 否 | 无需人工确认，具体类别单列 |
| 只有清单信息的对象 | 否 | 盘点对象，不表示已证明安全 |

只有有效的 DONE 语义结论参与计算。技术失败、失效、尚未复核不能当作安全。一个变量有多项复核时综合全部项，不能因其中一项安全就把整个变量判为安全；仍有静态疑似或未知项时保留对应待核实结论。补充覆盖等原有不确定边界继续保守保留。

人工已经确认的风险或安全记录保持原样；需补证、需重认和冲突，在对象属于上述人工范围时继续进入待办。AI 安全不会自动写入“人工确认无风险”，不会删除已有人工风险或冲突记录。概览提供独立人工风险/冲突入口，详情明确提示分析与人工记录的分歧。

## 实现与交互

- `current_results.py` 在同一 SQLite 读事务中，按已发布 AI 快照水位读取有效结果；兼容旧原文快照及 v1/v2 引用，按变量身份聚合，不加载整套 facts 或全部账本到 Python。
- 汇总、分页、筛选和待办采用同一投影。汇总按有限枚举组合单次分组，避免为每个计数重复执行投影。人工待办排序也将无需确认的对象放到后面。
- 概览显示当前风险、未知、安全和人工待办；原静态统计明确标为“原始静态分类”。安全计数区分静态、OpenCode 和联合证据来源。
- 变量及人工详情增加可读的 OpenCode 结论标签页。已复核对象默认打开最新真实答复；保留原静态证据、源码和人工历史，原始状态默认收起。
- 可见窗口每两秒查询小型版本标识；发布新 AI 结果或保存人工记录后更新概览、列表、选中对象及复核页。任务完成和跨页进入也会触发刷新，不需要重新扫描或手动刷新浏览器。
- 刷新保留人工草稿；其他窗口改变人工签署时保留原提交依据并提示重新核对，不静默覆盖或自动改签。
- 进入人工确认默认清空其它页面的筛选，只显示真正待办；继续上次位置时不再跳回已经安全的旧对象。概览卡片可直接进入对应完整列表。
- 人工保存立即更新选中对象和优先列表。变量名称、状态和来源改为分行展示，避免新增状态标签挤没变量名。

包内复验发现过一次切页竞态：进入人工页清空旧列表时，上一轮刷新仍在执行，新页面的强制刷新被丢弃，导致一直“读取中”。失败的原始 CLI 日志保留；已加入强制刷新排队合并，最终包重新执行连续切页与页面验收。不会以先前一次通过覆盖后续发现的问题。

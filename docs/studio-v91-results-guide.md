# OpenCode 复核后，怎样查看与人工确认

关闭旧版后台启动窗口，再运行本轮 v91 的 `ECRA.cmd`，继续使用原来的数据根。仅刷新旧浏览器不会替换仍在运行的旧版 Python 后台。已有结果会按最新规则显示，不需要为修正待办数重新扫描或调用模型。

升级前保留旧工具和数据根。若在旧工具中编辑过案例库或工程背景，先备份旧工具 `config/concurrency_cases.md`、`config/review_context.md`，再将它们放到新工具相同位置；新任务仍只使用这两份 config 原文件。

1. **项目概览**：看“风险/疑似”“无法判断”“安全”“人工待确认”。点击卡片可打开对应列表。安全卡片同时说明结论来自静态还是 OpenCode。
2. **OpenCode 复核**：从这里启动复核并查看原始 AI 结论。复核结果发布后，其它相关页面会自动更新；窗口重新可见后约两秒内检查更新。
3. **人工确认**：默认只列需要处理的风险、疑似和无法判断对象。静态安全、OpenCode 安全或误报不进入待办，显示“无需人工确认”。已经签署的对象也不再作为未处理待办；需补证或需重新确认的对象继续保留。
4. **查看依据**：选择对象后，已有复核答复默认显示在“OpenCode结论”标签。需要时切换“时序与访问”“调用与保护”“归档源码”；原静态分类和人工记录始终单独标明。
5. **填写与保存**：展开“填写人工确认”，填写确认者及依据后选择结果。暂时不能判断时点击“暂无法确认”，对象继续留在待办。切换页面和复核自动更新会保留当前窗口草稿，刷新或关闭窗口前仍应保存。
6. **更正与撤销**：到“人工历史”核对旧记录，填写撤销理由后点击“撤销上次确认”。适用对象会重新进入待办。其它窗口修改人工记录时，本窗口会提醒重新核对，避免覆盖对方签署。

“当前安全”表示当前静态或 AI 证据下的结论。归档源码没有重新验证、覆盖不完整或仍有未知时，不表示整套固件已经安全。OpenCode 不会代替工程师签名，也不会删除已有的人工风险记录；概览中的独立人工记录入口可继续查看它们。

截图中 STM32F103 归档的正确结果是：**安全 52、无法判断 4、容器 7、人工待确认 4**。原始静态“疑似 23”仍保留作追溯，不再代表复核后的当前风险数。

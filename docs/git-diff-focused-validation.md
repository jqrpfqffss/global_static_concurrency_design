# 差异清单收敛验收

上一轮验证了 21 项构造案例都能命中，却没有将“默认差异清单必须排除未改业务变量”作为验收条件。这使 95/96 行被展示仍被当作验收通过，是首轮验收的缺项。

## 为什么之前几乎展示全部变量

页面过滤本身生效，但输入给页面的集合已经过大：

1. 原影响工作队列同时沿调用边向上、向下遍历。修改 `Probe_Foreground` 后，上溯到未修改的 `main`，再下降到原串口 CLI 分支，形成无关扩散。
2. 任意全局语义或未解析依赖触发回退后，几乎所有变量都加入 `selected_symbol_ids`，将“暂时不能排除影响”混同于“有证据属于本次差异”。

## 当前展示规则

后台仍分别完成两个版本的完整构建、事实提取和并发分析。显示层与本轮复核队列使用同一份差异集合：

| 对象 | 当前行为 |
|---|---|
| 声明、初始化、访问、上下文、保护、调用图、覆盖、冲突或分类发生变化的变量 | 进入默认差异清单 |
| 变更函数调用到的深层变量、真实共享数据读者、消费变化返回值的调用者 | 根据定向依赖进入差异清单 |
| 仅与变更函数共享未修改的 `main` 或调用祖先 | 不据此入选 |
| 被改变的公共宏 | 根据函数实际消费的宏及传递定义关联；包括命令行宏与预定义宏有效值 |
| 仅因全局缺口暂时不能排除影响，缺少具体变化或依赖证据 | 保留在覆盖说明，不自动填入差异清单 |
| 未列出的原有静态候选、完整变量和访问证据 | 保留在后台 JSON、SQLite、覆盖及完整 findings 中，不重分类为 SAFE |

被调用函数的返回值只有在实际被使用时才向上游传播。普通 void helper 或被丢弃的返回值不会把调用者的其他变量拉进来。参数、共享读写、上下文、保护与物理重叠仍参与分析，深层变量无需自己被编辑就能入选。

声明和初始化器也记录宏消费者，避免只修改全局初值却不修改函数体时漏报。`__COUNTER__` 另保留 TU 展开顺序和环境依赖，前序展开、定义乘数或声明顺序变化仍能关联后面的消费者；该路径对同 TU 的 counter 消费位置保持保守。已恢复的 IRQ 优先级、启用状态和抢占关系按实际执行上下文比较；无法映射到具体 IRQ 的配置保留为未排除影响。

`selected_symbol_ids` 保存默认差异集合；`conservative_symbol_ids` 保存仅有未排除潜在影响的集合。后者在 HTML 的覆盖说明和 Markdown 中明确计数。存在这类不确定性时，最终结论保持 INCONCLUSIVE，运行状态保持 INCOMPLETE，不能利用空清单声称安全。

当前粒度仍是函数及已恢复的存储/数据依赖，不保证逐语句的最小集合。变更函数内的只读、安全或完整保护访问，也可能作为相关上下文列出。

摘要 schema 从 5 升为 6；旧摘要及旧引擎缓存不会作为本轮结果复用。配置无需新增开关。

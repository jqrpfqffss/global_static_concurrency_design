ECRA Windows Full Portable（Windows 10 1903+ / Windows 11 x64）

双击 ECRA.cmd 打开 Studio；首次在“新建工程”配置真实固件与构建，开始扫描后在
工作台查看结果和覆盖范围。人工确认需显式保存；关闭浏览器后，使用同一数据根再次
启动即可继续。把整套工具解压到非 C 盘可写目录，默认保存到解压根目录的 workspace。
如需选择其他数据根，请使用 workspace/data-roots 下的数据目录。关闭启动窗口或 Ctrl+C
停止服务；仅关闭浏览器标签不会停止服务。操作说明见 STUDIO-GUIDE.md。

以下是兼容命令行入口。可选 Git 差异模式：配置 analysis.git_diff 或执行
.\ECRA.cmd --scan-mode diff run --no-review。
base_ref/current_ref 指定 project.root 固件仓库中直接比较的两个分支、标签或提交。
current_ref 默认 HEAD；指定其它引用时自动隔离分析，无需切换分支。完整包默认包含 MinGit（tools/git/cmd/git.exe）。
doctor 会列出 Git 实际路径和版本。旧包可对照 portable-lock.json 的 git_runtime_version
与 FILES.sha256.json 的 tools/git/ 条目；两者均缺少且入口不存在，表示没有交付记录。
有记录但文件缺失时请从已校验 ZIP 完整解压到新目录；若有额外嵌套目录，请核对 ZIP 层级。
旧包普通全量仍可使用；差异比较、版本选择及包含未提交输入的扫描需要 Git。
首次比较需独立构建基准；
正常 CLI 扫描也发布到 Studio 数据根，使用 Studio 打开；只有显式 --legacy-output
兼容模式才生成旧 index.html。差异范围之外不代表安全。不要单独删除报告引用的
基准 worktree/事实。

1. 解压整个 ECRA-Portable 目录；不要只复制 ecra.cmd 或工具 exe。
2. 备份并编辑 config/semantics.yaml 的 project.root、扫描目录、上下文和复核设置。
3. cmake.generator 应保持工程实际设置：MinGW Makefiles / Ninja / Unix Makefiles。
   STM32 工程必须用其真实 ARM 工具链文件；MinGW GCC 仅用于 Windows 本机构建。
4. build_dir 可沿用旧配置；默认实际构建目录在工具 workspace/projects/<工程身份>/builds/。
   Git 两个版本分别构建，不共用 CMakeCache。使用 analysis.cmake.location: workspace。
   工具只清理有当前源码所有权的专用构建目录。
   generator、工具链、target 和参数保留，构建失败不会回退或忽略。
   正式结果在活动数据根的 scans/<扫描ID>/；中间构建、缓存和工作文件也保存在工具内。
   仅兼容 --legacy-output 模式使用 workspace/projects/<工程身份>/results/index.html；
   可用 analysis.output.location: custom 及绝对 custom_dir 选择工具内的数据根。
   升级请保留完整 workspace。AppData 旧数据迁移和旧副本清理见 docs/workspace-storage.md。
   旧固件 .ecra 按身份、文件结构及哈希复制，原件保留；旧收据需重新校验。
   current_ref: HEAD 默认使用固定提交的独立工作树，未提交业务修改未纳入扫描。
   更多规则见 docs/workspace-migration.md；当前 Studio 数据合同见
   docs/rearchitecture/portable-and-user-guide.md。
   显式启用 analysis.git_diff.include_uncommitted: true 的受控CMake工作字节模式，
   全量和差异扫描都要固定、重新核对完整SDK。该阶段可能较长，请查看任务阶段与
   日志；正常停止保留已校验TU缓存，恢复前仍须重新核对输入。
5. 在 PowerShell 中运行：
   .\ecra.cmd --help
   .\ecra.cmd doctor
   .\ecra.cmd run --no-review
   .\ecra.cmd report
   .\ecra.cmd status
   使用外置配置时，每条命令均带同一 --config，例如：
   .\ECRA.cmd --config D:/MyProject/semantics.yaml run --no-review
   .\ECRA.cmd --config D:/MyProject/semantics.yaml status
   .\ECRA.cmd --config D:/MyProject/semantics.yaml report
   report 重新生成只读投影，不会重新验证旧源码。退出码 2 表示仍有待办/覆盖缺口，
   不是全工程安全；失败和中断查看实际阶段及日志，不删除旧结果以重试。
   ECRA 按工具链需要使用 8.3 短名称或 workspace/a 下的 ASCII Junction。
   无法取得足够短的英文路径时，请将整套工具移到类似 D:\ECRA 的非 C 盘短英文目录。
   CMake 会将自身路径解析回真实目录，因此还为同一 GNU Make 4.4.1 增加
   Windows activeCodePage=UTF-8 manifest。所有非资源代码段保持不变，不改变
   Make 版本或构建逻辑；原始/产物 SHA256 和适配配方在 tools/mingw/make-utf8.json
   与 portable-make-utf8.py 中保留。不会修改系统全局代码页。
6. build: false 只配置并导出编译数据库，不执行固件构建。
   doctor 执行真实配置，但不执行构建/扫描；各验收状态分别报告。
7. OpenCode 不随包分发。需要复核时，在目标电脑独立安装 OpenCode、配置模型和认证，
   将其加入 PATH 或在 review.command 填写绝对路径，然后启用 review.enabled 并运行：
   .\ecra.cmd review-resume
   续跑会跳过已归档且通过校验的项目。用 review 重新复核全部疑似与未知，
   用 review-failed 仅重试技术失败项。
   启动 ECRA 时可保留已设置的 OPENCODE_DB，ECRA 使用该绝对路径的会话库，
   允许位于 workspace 外。未设置或为空时，使用 workspace 内的独立会话库。
   复核归档、日志、配置副本和临时目录均保存在 workspace。
   可选 review.session_cleanup.enabled: true（默认 false）。使用原生 OpenCode
   1.18.35 时，变量归档后仅清理本轮归属已验证的会话，技术失败和 ECRA
   原始证据保留。自动压缩仅适用于 ECRA 创建的独立库。清理失败可用
   review-resume 按原库补偿，已归档结论无需重跑模型。
   doctor 找到命令不代表模型连接或真实复核已通过测试。
8. 构建子进程只使用内置工具及 Windows 系统目录；OpenCode 保留宿主 PATH。
   若工程明确需要外部工具链，设置 analysis.cmake.allow_external_toolchain: true。
   外部路径会被诊断记录，不会悄悄替换工程的编译器、宏或架构参数。
9. 独立重复验收（工作目录必须尚不存在）：
   .\runtime\python.exe -B .\validate_portable.py --bundle . --work D:\ecra-check-new
   此验收会校验出厂文件 SHA256；编辑用户配置后需使用原始 ZIP 解压副本运行。

构建机打包：
  powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare_portable_cache.ps1
  powershell -NoProfile -ExecutionPolicy Bypass -File .\build_portable.ps1 -OutputDir .\dist-new
  离线先执行 prepare_portable_cache.ps1 -OfflineCheck；build_portable.ps1 从不联网。
  可提供 -PythonSource -CMakeSource -NinjaSource -MinGWSource -MinGWMakeSource -ArmGccSource。
  已准备其他工具时，联网运行准备脚本即可补齐 Git。离线可将官方 MinGit-2.56.1-64-bit.zip
  放入 .tools-cache/downloads 再运行 -OfflineCheck，或用准备脚本的 -GitSource 指定本地归档。
  打包时可用 -GitSource 指定已有的完整 MinGit x64 目录；默认从缓存读入，来源和版本写入锁文件。
  -VcRuntimeSource 可指定完整 VC++ x64 运行库目录/ZIP 或锁定的微软官方 redist exe。
  来源必须为完整目录或 ZIP（上游 MinGW .7z 需要构建机安装 7-Zip）。
  旧版本缓存不会复用；缺失 DLL、错误版本、外部编译器或真实构建失败会终止打包。
  已存在输出目录中的包和用户配置不会被覆盖；请改用新的 OutputDir。

验收日志位于 OutputDir/portable-evidence，包含每条命令、退出码及完整日志。
只有解压后的隔离构建也通过，candidate.zip 才会重命名为 ECRA-Portable.zip。
portable-lock.json / VERSION.txt 记录版本与来源，FILES.sha256.json 记录逐文件校验。
保留各工具附带的许可证；转发工具时须遵守对应许可证和源码提供条款。
ARM 编译器、binutils、头文件、库和标准 GDB 完整保留。上游可选的 gdb-py 和
gdb-add-index-py 因需要外部 32 位 Python 2.7 而不随 ECRA 包分发，清单中明确记录。
libclang 所需的 MSVC 运行库以应用目录方式内置，来源为微软签名的官方 x64

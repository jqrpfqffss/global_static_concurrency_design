# 大型项目排查与验收

## 本次修复针对的问题

1. 未使用变量、常量、未调用函数中的变量原来容易落入“无法判断”或没有候选的清单状态。现在以明确的安全证明条件筛除，并保留原因。
2. 工程级缺口原来可能污染大量内部变量。现在区分外部可见对象、未逃逸内部对象、内存访问缺口和入口缺口；不通过降低整体覆盖要求来掩盖真正的盲区。
3. 补充声明原来没有逐变量候选。现在每个非安全变量都进入自己的复核项，并校验变量总数、唯一 ID 与队列覆盖。
4. 复核包原来主要附带最短调用链，回答格式也不能验证访问点是否逐个处理。现在补全所有上游调用者，附带逐项核对清单；首轮、反证、缓存恢复和报告刷新校验原始答案及证据包。
5. 逐文件覆盖原来重复遍历编译单元、头文件和变量。现在预先索引包含关系、变量声明位置和文件缺口，降低大型工程重复遍历开销。

## 本地安全筛除条件

| 原因代码 | 结论依据 |
|---|---|
| `ONLY_READS` | 所有有效访问均为读取，无相关未知写入/逃逸/硬件证据缺口；读者入口未知本身不制造写入 |
| `NO_RUNTIME_ACCESSES` | 当前构建没有运行期访问，定义完整且没有相关缺口 |
| `UNREACHABLE_ACCESSORS` | 全部访问属于入口不可达函数，调用图、入口发现与构建证据允许作出此证明 |
| `SINGLE_ACCESS_SITE` | 唯一读写位置只属于一个不可重入上下文 |
| `SINGLE_EXECUTION_CONTEXT` | 全部有效读写属于一个不可重入上下文 |

以上针对当前构建的并发风险。未编译文件、条件编译变体仍作为补充声明，不当作实际构建的安全证明。未知外部库可以访问外部链接变量；没有其实现时，不能仅凭已看到的读取就证明该全局变量只读。地址逃逸、未知指针、汇编宏/包含、解析失败和多核模型缺口仍需处理。

汇编编译项中的函数引用会阻止把相应函数误判为未调用；已经识别的 main/中断根不会因此重复产生未知入口。汇编变量引用单独保留；汇编宏、包含等未展开语义明确保留缺口。此检查不是完整的汇编解释器。

## 可复现回归

2026-09-15 本机验收：全套 **167 项测试通过**（118.314 秒）；最终报告展示与完整清单针对性检查另有 12 项通过。规模夹具结果为 **250 个文件、1001 个变量、1000 个静态安全、1 个保留的并发风险候选**。复核协议模拟覆盖 250 项，不涉及真实模型推理。

```powershell
python -m unittest discover -s tests -p test_large_project.py -v
python -m unittest discover -s tests -q
```

`tests/test_large_project.py` 使用真实 libclang 和临时工程，覆盖：

- 125 个 C 文件 + 125 个头文件，完整执行 CLI、补充盘点、分析、JSON/SQLite/Markdown/HTML 和离线复核队列生成。
- 1001 个变量：1000 个明确安全，1 个由两个中断共用同一写入函数的风险候选。逐一检查名称、唯一身份、250 个文件的覆盖记录和队列归账。
- 未调用递归环、未调用写入函数、只读但入口未知、外部库与内部变量隔离、函数地址、构造属性、可重入任务、汇编引用。
- 已解析的局部对象指针、函数指针解引用、DMA 缓冲区与指针本体分离。
- 未包含头文件与缺少定义变量均有逐变量复核项。
- 250 项复核协议模拟：4 个 worker、首轮限额 73 项、下一轮恢复剩余项；故意漏掉访问点后拒绝并重试；所有项不重不漏，已完成项复用缓存。
- 非最短上游路径、超出源码附带上限的函数、损坏证据包、单项准备失败不阻塞后续项。

模型部分使用明确标记的模拟进程，仅验证协议、队列和恢复机制。它不代表真实 OpenCode 已逐项复核某个用户工程，也不代表模型准确率或硬件验证结果。

## 迁移后如何核对结果

1. 运行完整 `run`。核对 `coverage.file_coverage` 是否包含预期文件，包括零变量文件；处理解析失败与补充盘点缺口。
2. 核对 `coverage.variable_accountability`：`missing` 和 `duplicate_ids` 必须为 0；`screened + queued == total`。每个文件的 `symbol_ids` 可与变量清单交叉检查；同一全局变量在多个文件声明时，文件计数之和不等于变量总数。
3. 在首页检查安全筛除原因、未知入口和阻塞项。不可达访问保留但不计入未知入口访问数。
4. 启用 OpenCode 后运行 `review`；`max_items: 0` 表示不限制本轮首轮复核项数。若设置了限额，继续运行 `review`，直到剩余项得到定论或明确缺少的证据。
5. 检查 `review_summary.variable_coverage.remaining`、独立缺口与整体分析状态。某个变量已经确认有问题，不代表其他变量完成了排查；`DONE + NEED_MORE_CONTEXT` 也不等于最终定论。

本次工具修复和规模回归不能保证任意大型 C/C++ 工程没有问题。真实工程还需要其实际编译数据库、入口、芯片/多核/DMA 配置和有效模型响应；不能把测试工程结论移作用户固件的结论。

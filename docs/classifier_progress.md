### 当前边界

- OPT-02 尚无完整 D-01…D-12 模式码、真正的逐见证消融或热点元素归因；当前上界只针对同一种 UNKNOWN 缺口。
- OPT-18 的直接 MMIO 识别尚不覆盖经局部指针、SPL/LL 初始化结构或函数调用传递的地址，也未建立 DMA 流身份、方向和生命周期。它只能防止已识别的直接发布被判安全。
- OPT-19 目前覆盖所列函数的缓冲区读写，不包含格式化输入输出、宽字符库或库函数返回指针的完整别名语义；未知库调用仍按逃逸保守处理。
- OPT-12 当前是一层访问器的保守读组，尚未用返回值来源摘要与 CFG 路径证明读组是否在同一次事务中被消费；完整一致性 v2 属于后续阶段。
- 规划阶段 0 的四工程基线与翻转审计尚未全部重放；阶段 1 的全部黄金风险守门、阶段 2–6 的完整精化以及阶段 7 的多工程抽样验收尚未完成。当前改动不能作为规划的最终验收。
- `validation/stm32_concurrency/verify_acceptance.py` 在当前工作区存在，规划中的 OPT-1A 遗留缺文件问题不再复现。

### V3 Betaflight 首次提取与解析修复

对 497 个 TU 完成全新提取；首次快照为 495/497 PARSED，原始事实约 1.264 GB，
92,298 个函数、41,632 条调用、3,191 个根变量、27,205 条访问，耗时 1,366.5 秒。
两处失败均保留在 `v3-betaflight-current` 的 worker 响应：
`accgyro_spi_icm56686.c` 的单字节非 UTF-8 注释使 Python libclang 绑定在读取
token 拼写时抛错；`cc2500_frsky_shared.c` 的函数指针赋值被当前 Clang 作为
错误诊断。探针分别验证跳过 C 注释 token 后得到 45 个变量 / 19 条访问，
保留函数指针不兼容诊断但取消 error 级别后得到 60 个变量 / 121 条访问。
两项通用解析修复已进入提取器，正在 `v3-betaflight-parsefix` 对全部 497 个 TU
重新提取，避免混用不同提取器的 worker 响应。第二次全新提取
`497/497 PARSED`，原始事实约 1.266 GB，92,474 个函数、41,690 条调用、
3,191 个根变量、27,224 条访问，耗时 1,559.78 秒（与全量测试并行，
不宜直接用作独立性能结论）。首次快照的 99.6% 解析率不能当作最终 V3 分类基线。

对失败 TU 增加编译器预处理后的标识符证据：只有所有变体都成功预处理，且没有
未解析的内联汇编时，目标标识符缺席才可缩小外部变量的缺失源码缺口；失败、缺少

V3 对 497/497 完整提取的事实启动分类后，在进入逐变量证据构建前已超过
1,014 秒（规划参考 780 秒 × 1.3）；工作集约 3 GB，CPU 持续计算。

### V2 Black Magic Probe 的性能诊断（基线仍在重放）

现有编译数据库含 192 个 TU，首次全新提取中 189 个解析成功；
`libopencm3/lib/cm3/sync.c` 的 3 条构建变体因 Clang 的 `__dmb` 内建函数类型冲突
解析失败。失败事实保留为 `PARSE_FAILED`，不能报告为完整解析。
初次分类在内存异常增长时被停止，原始事实保存在
`output/preopencode-benchmark/v2-blackmagic-current/raw-facts.json`。

诊断显示同一变量曾带约 4.7 万条入口缺口，证据索引中 52,462 条入口里有
52,399 条 `FUNCTION_ADDRESS`，分布在 546 个目标函数。已使同一缺口记录在变量
之间共享，并把同一目标函数的实际地址逃逸站点汇总为一个变量局部阻塞；
完整原始站点仍保留在 `facts['unknowns']`，汇总记录有站点数、样本和定位引用。
V0 四分类在该变化后保持不变。

V2 首次成功分类耗时约 505 秒，编译变量 1438：SAFE 81、NR 0、SUSPECT 356、
UNKNOWN 1001，`RR_build = 1357/1438 = 94.37%`，解析率 `189/192 = 98.44%`。
这是当前 `optimize_c` 的结果，与规划中 `optimize_z` 的 691 / 21.0% 不可直接比较。
UNKNOWN 原因允许重叠：地址逃逸 831、相关别名 744、未知执行入口 574、
缺失 TU 547。高比例是真实的当前引擎输出，尚未证明这些缺口可安全消除。

首次成功产物的 `root_cause_v2.json` 约 2.2 GB、分类索引约 3.1 GB。
字段统计表明根因文件中约 1.47 GB 来自相同多字段一致性访问列表重复附在成员上。
现已为一致性组生成稳定 ID，将全量访问 ID 集中保留在
`facts['multi_field_coherence']` 的唯一组中；成员只保存 ID、成员集、计数、
前 8 个访问 ID 和具体函数见证。修复后 V2 分类计数未变，重放约 401 秒，
根因 JSON 降至约 88 MB、分类索引降至约 1.02 GB；同版本的第二次确定性核对
和更大规模的 V3 仍需完成。

为避免更大工程在输出分类索引时额外构造完整列表，benchmark 写入器现按变量逐条
序列化 JSON 数组；用含嵌套值和 Unicode 的样例核对，与原 `json.dump(indent=2)`
逐字节一致。此项只影响基准产物写法，不改变分析器结论。
抽样清单默认每种 SAFE/NR 结论至少取 60 个（不足则全取），并从每种现有证明码
至少取 10 个（不足则全取）；这只是待做源码审计的确定性选择，不等于审计完成。

本轮全量回归：`python -m unittest discover -s tests -q` 504 项通过、1 项跳过；
`python scripts/verify_design.py --all` 成功，D01–D20 场景均生成验收产物。

### 大工程内部函数的可达性剪枝

V3 原始事实含 92,474 个函数定义，其中大量 `static` 头文件函数随 TU 重复提取。
新增通用可达性证明：以外部链接函数、已知入口、配置入口、向量表及无所属函数的
函数取址为根，沿直接调用、函数体内取址和注册关系闭包传播。
只有无入口路径的内部函数跳过指针方程；原始定义、访问和缺口事实均保留。
解析失败、构建对象缺失、未列入构建的源码或无法解析的汇编源存在时不剪枝。
分析后的可能入口集合与剪枝集合相交会中止扫描，避免生成错误 SAFE 结论。

V3 的完整提取事实上，证明可跳过 86,146 个内部函数的求解工作，涉及
71,907/91,807 条语义调用和 12,528/20,085 条指针约束；证明计算约 21 秒。
优化前一次运行约 70 分钟仍未完成分类；首次剪枝运行在约 11 分钟、30 万次
求值时仍有约 500 条待办方程，未满足 Stage A 耗时门槛，已停止。
收紧“死函数内部取址”的传播后，V3 的第二次运行在 17 分钟门槛时
仍有约 430 条待办方程、约 723 万个指向目标，Stage A 性能门槛未通过。
随后到 54 万次求值仍有 478 条待办方程、约 768 万个指向目标，
已停止以诊断剩余求解循环。V3 尚无完整分类结果，不计入分类质量验收。

V0、V1、V2 使用同一保存提取事实回放，分类索引分别与剪枝前逐项一致：
V0 19/0/23/7，V1 880/0/157/9，V2 81/0/356/1001。
V0/V1 分别跳过 1,179/2,544 个内部函数；V2 因 3 个 TU 解析失败而跳过 0 个。
新增单元测试覆盖直接调用、函数取址、配置入口、死函数内部取址、属性入口、
缺失源码回退，并用真实 C 头文件验证可达回调与指针写入仍被恢复。
最终代码全量单元测试 521 项通过、1 项跳过，
`python scripts/verify_design.py --all` 成功。

### 指针求解器性能复核与数组摘要实验

对不具有可分析函数体的外部调用，不再建立无人读取的形参位置；不透明返回值、
地址逃逸和标准库访问语义仍在调用点保守处理。V0/V1/V2 保存事实回放的四分类与
修改前相同，分别为 19/0/23/7、880/0/157/9、81/0/356/1001。
V2 的指针方程求值次数从 22,007 降到 21,174；上下文指针求值从 28,113 降到
26,350。V2 仍有 3 个 TU 解析失败，内部函数剪枝对此保持关闭。

尝试过深度优先任务调度，在 V2 回放中约 3,785 秒才完成，明显慢于先进先出
调度的约 427–486 秒，已撤回。V3 的热点跟踪把剩余增长定位于有限数组的
逐元素指针偏移、字节复制及不同对象指向集的合并；在第 54 万次方程求值时
仍有 478 条待办、约 768 万个目标成员，故没有可报告的完整分类。

另尝试了仅在环境变量开启时的有限数组偏移宽化和数组摘要压缩。V0/V1 未触发
宽化；V1 虽四分类未变，但摘要压缩改变了 3 个变量的访问和冲突见证，说明当前
表示法不能保证审计证据等价。该实验已从生产代码撤回，诊断日志留在
`output/preopencode-benchmark/`。此处既不能宣称 V3 性能门槛达成，也不能以
缩减证据的方式降低复核比例。
撤回实验后的全量单元测试为 522 项通过、1 项跳过；
`python scripts/verify_design.py --all` 再次成功。

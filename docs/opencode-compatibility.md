# OpenCode 直接运行与按需维护

CLI、Studio 和 Portable 沿用 `review.command` 参数数组及当前模型配置。基础准备只解析入口、准备本地目录及运行环境，接着直接派发实际 `run`。不执行版本查询、`run --help`、`db path`、临时 `protocol.db` 或 schema/迁移比对；没有版本白名单、主版本门槛、能力缓存门槛或替代模型探测。

`opencode-check --json` 和 Studio 的“检查本地启动条件（不运行 OpenCode）”共用本地检查。`ready` 只表示路径和配置能准备，不代表认证、模型或清理可用。版本显示“未查询”，为空不会禁用复核。实际输出仍须通过原有答案、会话事件和结束状态校验。

## 运行上下文

支持原生入口、显式 Node 入口及已支持的 Windows cmd/bat/ps1，保留空格路径和参数数组。提示词经 stdin 传递。ECRA 不替换企业包装入口，不通过 PE/Bun 元数据判断兼容性，不提交账号密码。

正式复核与按需维护共用准备好的模型配置 scope、认证副本和继承环境；不再嵌套创建空 HOME/XDG 探测环境。保留当前 HOME、USERPROFILE、APPDATA 和企业认证环境；ECRA 的临时文件、XDG 配置/状态/日志/缓存留在工具 workspace。显式 `OPENCODE_DB` 原样使用；未指定时使用本轮工作区数据库。

标准 `auth.json` 只是可选认证来源，不代表所有企业发行版的认证方式。可选 `review.runtime.auth_file`、`config_file`、`auth_plugins` 沿用现有配置。企业发行版对继承环境的具体行为须以该发行版实测为准。

## 归档与清理

清理开关保持原语义。基础复核不调用维护初始化。新库尚未形成文件身份时，在清理账本记录待绑定；实际 `run` 结束后绑定，无法确认则保留会话。恢复时不凭空绑定旧的未知库。

只有对应调用可靠归档为 DONE 后才安排删除。仍核对真实 Session ID、调用和归档摘要、数据库文件身份、标题、目录、项目、父子会话及原进程结束状态。用户启用清理后，维护才验证实际数据库路径和受控回环 API。健康检查只要求 `healthy=true`，不比较健康响应或 session 的版本字段。

维护失败保留 DONE 与会话、记录独立状态，不重新调用模型，不阻止后续复核。共享库不自动压缩或强制 checkpoint。独立库保留原有按需压缩功能。

## 故障和恢复

入口不存在或本地目录无法准备属于初始化错误，未派发项保持待处理。实际 run 的认证提示、非零退出、超时或无效输出属于调用错误，保存脱敏日志、参数、cwd、配置来源、数据库、阶段、耗时和回收前后状态。CLI 启动尝试单独计数；启动后模型请求总数未知时为 null，存在响应证据时另记录观察到的下界。回收退出码不覆盖原始超时或取消。

旧静态检查点、合法 DONE、人工确认和队列保持。兼容映射只覆盖本次确切的复核启动/诊断变更；未来答案契约变更仍产生新身份。不读旧版本或探测缓存作为放行依据。

## 验证边界

`tests/test_opencode_direct_run.py` 使用记录 argv 的测试入口，拒绝任何预检命令，覆盖归档、续跑、失败重试、本地 CLI/Studio 检查和真实子进程故障；它不是企业模型验收。`test_review_session_cleanup.py` 保留精准删除、恢复、人工确认和归档安全回归。

最终 Windows 企业版和 Portable 实测状态见本轮交付报告。缺失现场程序、数据库或模型授权时，不用官方替代程序或模拟响应冒充真实复核成功。

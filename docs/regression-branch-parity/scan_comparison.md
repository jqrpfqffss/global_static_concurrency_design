## 资源与完整测试

作为当前快照，A 第 3 轮在 9,147.156 秒因 `MemoryError` 退出，提交峰值约 50 GiB。C1 第 2 轮在 13,480.047 秒因记录器异常中断，提交峰值约 9.36 GiB。两个失败轮都保留静态中间证据。B 第 3 轮已经通过输入、提取、分类验证，进程尚未退出。各轮带时间戳的耗时、峰值、缓存及输出状态随隔离目录的 `acceptance-current.json` 更新。

Windows Job 记录整棵进程树的提交内存峰值，同时记录采样工作集和私有内存。大型扫描与测试共用这台 Windows 主机，耗时只作为本轮实测。扫描使用 Python 3.10.9。首轮 C 用本机 Python 3.10.11 执行完整测试发现命令。1,821 项中 1,817 项通过、3 项跳过、1 项 MinGW 用例出错，终态为 **FAIL**。后续对照证明是新增 C++ 用例改变了当前进程的工作目录。修正测试隔离后，真实 CMake 与 MinGW 原顺序回归的 16 项通过，实际 CLI 返回 2 并生成可深度校验的 SQLite。最新引擎的完整测试和 INAV 第 4 轮复核使用独立收据。各专项复测及收据位置见 [acceptance.json](acceptance.json)。

最新引擎对真实串口工程分别以 8、4 个进程冷扫，再使用同版缓存热扫。三次权威事实摘要仍为 `350d5b1fb5c7486d1bfc59f4dfc3cdb2597241538caad082fc9fc3ded31b7d6f`，热扫命中 `20/20`。实际 Studio 打开了新串口结果、新 ARM 夹具结果和旧版 B 串口结果的隔离副本，三者均完成两次浏览器会话及实际导出，浏览数据与各自 SQLite 一致。专项回归包括静态分析 130 项、Git 差异扫描 49 项、存储与复核 62 项和 Studio 前端 32 项。OpenCode 流程通过测试响应验证。

Prusa-Firmware-Buddy 的历史本机记录包含 771 TU 和旧引擎约 54 GB 的单进程提交峰值。本轮选择独立 ARM 构建夹具覆盖其所需的任务、DMA、C++、别名和缺口反例。没有重复构建或扫描 Prusa。多核仍应在双镜像证据模型下独立核验。

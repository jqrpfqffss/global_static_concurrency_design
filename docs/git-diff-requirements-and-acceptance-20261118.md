# Git 差异扫描需求与验收清单

Git 差异扫描需要回答：本次修改影响了哪些全局或 static 存储对象，哪些对象需要重新审查，当前并发结论相对基准发生了什么变化，以及哪些结论仍受证据缺口限制。准确性和证据完整性优先于扫描速度。

需求确认日期：2026-11-18。Q1 至 Q22 已确认。最终范围是分支或 tag 之间的差异扫描：工作区编辑不参与比较，后台完整记录影响分类，前台只展示差异相关变量，人工确认沿用不开启差异扫描时的规则。代码对照基线为 `optimize_ccc` 分支提交 `ff48cbfda32b143d3922f119b70481352b11ea81`。

下方差距表记录实施前的代码基线。六个阶段现已完成，阶段四至六于 2026-11-20 完成最终联合验收。各阶段历史记录保留当时的交付范围；实际改动、分批验证、真实工程三轮结果和剩余边界见文末实施记录。

**已确认需求**

| 问题 | 已确认规则 |
|---|---|
| Q1 首要产出 | 保留全部受影响对象，优先展示需要审查的风险。分别表达新增风险、已有风险受影响、安全对象和无法判断。受影响变量不等于新增风险。 |
| Q2 比较含义 | 严格比较用户选定的两个分支或 tag 的最终状态，显示实际固定的提交身份；不自动改为共同祖先比较。 |
| Q3 不确定影响 | 无法排除影响的对象单独展示为待核实，能够逐项查看原因和证据。存在这类缺口时，不能凭明确差异清单或人工待办为空宣称本次修改安全。是否需要人工确认遵守 Q21，不增加影响归属人工流程。 |
| Q4 效率目标 | 首先减少人工审查量并保证结果准确。允许两侧完整分析和经校验的缓存复用，不要求耗时与修改行数成正比。 |
| Q5 构建范围 | 只对本次选定固件的真实构建作并发结论。其他板卡、未启用分支和未加入构建的文件单独注明未纳入分析；不同构建分别扫描。 |
| Q6 目录范围 | 纳入和排除目录控制变量定义归属。范围外代码对目标变量的调用、指针访问、回调等证据仍须保留。 |
| Q7 间接影响 | 纳入真实调用、被消费的返回值、共享数据、宏、执行上下文和保护变化的影响，不限于改动文件。仅共享未修改的调用祖先不构成影响依据。每项应能解释传播关系，并保留未修改的相关冲突访问。 |
| Q8 三类处理 | 有具体依赖的归明确影响；仅有函数级等保守关联的归待核实；有无关性证明的归可排除。不能仅因函数整体被修改，就将其全部访问变量认作明确影响。 |
| Q9 对象粒度 | 能区分的结构体成员、数组元素及 static 实例分别判定。存储重叠和不确定关系保留理由；容器仅汇总，不重复计作风险。 |
| Q10 比较依据 | 两侧使用同一引擎和审查规则，各自使用真实版本输入。风险变化基于静态证据，AI 和人工意见分别标明。既有综合当前结论及人工规则继续使用，不将其混入静态变化矩阵。手工入口、保护等声明若不能同时适用于两侧，必须明确指出。 |
| Q11 对象与风险变化 | 新增对象的当前疑似风险必须进入风险清单。删除、移出构建、匹配失败分别说明；改名或存储形态变化无法可靠匹配时保留两侧记录，不能据记录消失宣称修复。 |
| Q12 加重或减轻 | 展示新增写者、保护变化、冲突关系变化等事实。风险加重或减轻需要相应判据或复核，不能仅用访问次数、路径数量或相同分类推断。 |
| Q13 三态变化 | 采用下文九格矩阵，区分风险新产生、现在才发现疑似风险、安全证明取得或丢失，以及旧风险尚不能关闭。 |
| Q14 覆盖相关性 | 逐对象说明缺口限制哪些结论。已知冲突与覆盖不完整同时保留；无关缺口不推翻独立安全证明；排除关联必须有证据。覆盖百分比不是安全判据。 |
| Q15 风险关闭证明 | 宣称原疑似风险可能已消除，需要基准冲突、当前安全证明及两者对应关系，并核对当前全部相关访问和可能推翻该证明的缺口。 |
| Q16 有效局部结果 | 基准和当前采用一致规则。输入固定且构建依据可信、只有局部提取缺口时，保留可成立的对象比较，其他对象标待核实或不可比较。输入、构建身份或产物校验无效时，本次比较失败并保留旧有效结果。部分结果不得冒充完整验收通过。 |
| Q17 共享无需复核 | `SHARED_NO_REVIEW` 保持独立，保留豁免依据，不合并进安全。疑似转为该状态表示满足免复核规则，不计作已证明安全或风险修复；该状态转疑似表示豁免条件失效。证据缺失时不能继续沿用豁免。 |
| Q18 输入模式 | 只考虑分支或 tag 的差异，可组合分支对分支、tag 对 tag、分支对 tag。提交 SHA 用于固定所选版本；工作区、暂存区和未跟踪修改均不作为 Diff 源码输入，不提供暂存区独立扫描。非 Diff 原有行为不在本轮修改范围内。 |
| Q19 扫描与编辑隔离 | 扫描绑定所选分支或 tag 的固定提交及本轮真实构建输入，和原工作区继续编辑无关。固定后的任务和历史结果不因工作区编辑、暂存、切分支或引用推进而改变版本；新扫描重新解析所选引用。实际冻结输入或归档证据损坏仍须失败。 |
| Q20 三类归账范围 | 对两侧范围内全部已识别比较对象记录明确影响、待核实或可排除及理由。没有排除依据不得默认为可排除；未识别对象以区域性覆盖缺口表示，不能冒充已逐对象分类。容器只汇总，不重复统计。 |
| Q21 展示与人工确认 | 界面只展示扫描差异部分的变量；明确影响与待核实分别可查，已证实删除项保留基准证据，可排除对象留在后台归账。人工确认资格、待办、状态、历史及提交效果沿用不开启 Diff 时的规则，不新增影响归属人工事件或确认状态。 |
| Q22 独立全量对照 | 对照事实不一致仍阻止发布。仅因局部提取缺口无法完成对照时，可保留其他有效局部结果，但明确标为对照未完成，不能计完整验收通过。输入校验失败或其他未被证明可局部化的故障，不得笼统降级为允许发布。 |

**判定维度**

对象变化、修改影响、静态风险和覆盖状态需要分别记录。一个变量可以同时是“身份未变、间接影响、当前疑似、覆盖不完整”；当前静态安全也不自动意味着已证明它不受本次修改影响。

| 维度 | 回答的问题 | 不允许的混淆 |
|---|---|---|
| 对象变化 | 是否新增、删除、移出构建、改名或匹配不确定 | 未提取到对象不等于真实删除 |
| 修改影响 | 明确影响、待核实还是有依据可排除 | 仅同文件、同函数或同调用祖先不自动等于明确影响 |
| 当前静态分类 | 安全、疑似、未知或共享无需复核 | 未知不等于安全，免复核不等于安全证明 |
| 风险变化 | 同一对象的两侧证据支持何种变化 | 首次看见疑似不自动等于本次新引入 |
| 覆盖 | 变量论证、影响范围和工程整体各有什么缺口 | 工程不完整不等于所有变量未知，局部安全不等于工程完整 |
| 产物有效性 | 结果是否来自可信、固定的输入并通过必要一致性校验 | 发布成功不等于覆盖完整，也不等于没有风险 |
| 复核意见 | AI、人工分别如何评价结果 | 复核意见不改写静态比较输入；其对综合当前结论和人工待办的作用沿用原规则 |

三类影响是后台机器分析的归账，不是新的人工状态机。后台对已识别比较对象完整分类；前台展示明确影响和待核实对象，并保留真正删除对象的基准侧记录。可排除对象、无关变量和全量后台清单不扩入普通差异列表；清空搜索或普通筛选仍保持 Diff 范围。

人工待办等于差异展示集合与既有人工待办规则的交集。在同一对象、同侧事实、同样 AI 和人工记录下，开启或关闭 Diff 不改变该对象的综合当前结论、是否需要人工确认、确认状态和提交效果，只改变它是否属于本次展示集合。影响待核实可以继续存在，而原规则决定的人工待办为零；两者不得互相替代。

分支或 tag 在启动时解析并固定为提交 SHA。实际构建消费的配置、编译数据库、SDK 和 Git 元数据也须作为本轮输入被固定或有效校验。后续校验针对这些实际输入，不因再次解析分支名得到不同提交就把已固定结果改指向新版本。普通工作区编辑与真正的固定输入损坏必须分别处理。

**安全 疑似 未知的变化矩阵**

前提是两侧输入有效、可靠匹配同一存储对象。安全指所选模型与构建范围内有有效静态证明；疑似不是已确认缺陷。新增、删除、不可匹配对象不强行进入本矩阵。

| 案例 | 基准到当前 | 预期表达与计数边界 |
|---|---|---|
| R01 | 安全到安全 | 安全结论保持；相关证据变化仍可展示。 |
| R02 | 安全到疑似 | 新增疑似风险。 |
| R03 | 安全到未知 | 原安全结论不再有充分依据；尚不能证明新增冲突。 |
| R04 | 疑似到安全 | 原疑似风险可能已消除；必须具备 Q15 的证明。 |
| R05 | 疑似到疑似 | 疑似风险持续；展示证据变化，加重或减轻遵守 Q12。 |
| R06 | 疑似到未知 | 原风险尚不能关闭；当前证据不足，不计修复。 |
| R07 | 未知到安全 | 当前已取得安全证明；不计为修复了已知风险。 |
| R08 | 未知到疑似 | 当前发现疑似风险；不能证明本次新引入，不计入 R02。 |
| R09 | 未知到未知 | 仍待核实；展示缺口新增、消失或变化。 |

`SHARED_NO_REVIEW` 单独展示和统计。疑似到共享无需复核使用“当前满足免复核规则”；共享无需复核到疑似使用“免复核条件失效，当前存在疑似风险”。任何此类豁免都须有仍然有效的依据。

**覆盖不完整时的规则**

| 证据情形 | 允许的结论 |
|---|---|
| 已有可复核冲突，同时存在未知调用等缺口 | 疑似与覆盖不完整同时保留。 |
| 没有充分冲突证据，缺口可能隐藏写者或执行上下文 | 未知与覆盖不完整；不能以未发现冲突判安全。 |
| 无关 TU 解析失败，且有作用域或依赖证据证明与目标隔离 | 保留该变量独立结论；工程整体仍显示缺口。TU 指单次编译处理的源文件及其包含内容。 |
| 保护诊断未解析，但有不依赖该保护的单前台等完整证明 | 可保留安全结论，说明诊断为何不影响该证明。 |
| 安全证明依赖的访问、执行上下文或保护证据缺失 | 不允许用该证明关闭旧风险。 |
| 定义对象的 TU 提取失败，导致一侧缺记录 | 对象存在性或匹配待核实，不能计作真实新增或删除。 |
| 输入固定、构建可信，基准或当前存在局部提取缺口 | 对称保留有效局部比较，标明不可比较区域。 |
| 输入无法固定、实际构建不确定或产物校验失败 | 本次比较失败；保留旧有效批次并明确其身份。 |

“疑似风险可能已消除”的证据应能够从基准冲突定位到当前证明，说明原交错如何被排除、当前其他访问是否也受覆盖，以及剩余缺口能否推翻该证明。不能仅比较 finding 数量或以某个覆盖百分比通过。

**实现范围与优先级**

本轮目标覆盖比较语义、差异结果展示和必要一致性校验。不开辟工作区扫描或暂存区扫描流程，不新增影响归属人工确认状态机，不在差异页面增加全量变量浏览入口。原非 Diff 的输入方式、综合当前结论与人工确认规则保持原语义；公共组件调整必须验证这种等价性。

| 优先级 | 工作内容 | 解决的风险或缺口 |
|---|---|---|
| P0 | 分支或 tag 固定输入与结果身份，冻结实际构建消费的元数据，区分原工作区变化与真实输入损坏 | 避免版本漂移、工作区污染和无关编辑造成结果失效；G11。 |
| P0 | 对象存在性、相关覆盖门禁、九格变化、共享无需复核独立转移及旧冲突关闭证明 | 避免把漏提取当删除、未知当修复、豁免当安全，以及缺证据时错误关闭旧风险；G05 G06 G07。 |
| P1 | 有向影响精度和全部已识别对象三类归账 | 控制函数级误扩散，同时保留无法排除的对象和理由；G01 G02。此项是允许两侧局部结果的前置条件。 |
| P0 | 在对象与覆盖门禁完成后，对称支持局部结果并分流独立对照状态 | 消除两侧不对称，保留有效证据且不放过事实不一致；G08 G12。 |
| P1 | Studio 只展示差异变量，静态变化与原综合结论分列，人工规则等价，发布完整性清楚 | 完成可理解、可操作的差异结果；G03 G04 G09 G10。 |
| P2 | 冷热缓存、损坏缓存恢复和真实工程规模验证，定位耗时与存储瓶颈 | 验证优化不改变事实、归账和结论，不设未经测量的速度承诺。 |

优先级表示错误后果和投入重点，实施顺序以阶段依赖为准。每阶段都完成其对应检查，低优先级的必要验收也不可省略；正式交付还须通过跨阶段和非 Diff 回归。

**分阶段计划**

一个案例覆盖多层时，阶段内检查本阶段负责的契约；核心判定层通过不等于生产扫描或界面整条流程通过。阶段六必须完成跨层验收。

**阶段一实施记录（2026-11-18）**

本阶段实施范围为 G11 中的固定输入身份及相关准入、恢复和发布校验，完成时尚未开始阶段二。

- Diff 入口仅接受分支或 tag；轻量与附注 tag 均解析到提交。HEAD 作为所在分支的便捷别名，游离 HEAD、裸 SHA 和提交表达式要求改选明确分支或 tag。两侧比较固定后的提交尖端，不自动采用共同祖先。
- 两侧共用一份自包含的私有 Git 镜像，包含固定引用、对象、仓库配置及 attributes/exclude。镜像不再从原仓库刷新；引用或有效配置变化后的新扫描使用新身份与新工作树，保留旧扫描输入。
- 固定本轮有效配置；当前侧、基准侧、补丁和版本内编译数据库都使用固定输入。Studio 的预检查与正式扫描传递同一份输入身份，避免交接时再次解析移动的引用。
- 恢复和发布验证私有提交、源码、配置、补丁、基准证据及两侧实际编译输入闭包。原工作区继续编辑、暂存、切换分支或更新引用不参与这些校验；外部 SDK、编译器和系统/全局 Git 配置仍必须通过真实输入一致性检查。
- 旧 `include_uncommitted: true` 的 Diff 启动时明确提示迁移。界面只在全量扫描显示未提交输入选项；保留旧设置时提供显式取消入口，不自动改写。原非 Diff 冻结输入及显式 full 覆盖继续保留。

**阶段二实施记录（2026-11-19）**

本阶段处理 G05 至 G07 的比较对象与静态风险证据契约，并为 G06 的缺记录处理和后续 G08 提供对称数据模型。未实施阶段三的影响精度/三类归账，也未放开生产基准扫描的部分解析。

- 比较摘要升级为 `SUMMARY_SCHEMA = 9`，结果增加 `comparison_schema = 1`。每个对象保留定义、所属编译单元、实际静态证明、访问引用、冲突引用及相关缺口；摘要记录真实构建范围、逐 TU 解析状态和失败变体的预处理排除依据。原生数据库读取与原有摘要读取使用同一套算法，旧缓存因版本及引擎身份变化重新计算。
- `object_change` 分别记录基准/当前的 `OBSERVED`、`CONFIRMED_ABSENT`、`NOT_OBSERVED`，以及新增、进入构建、删除、移出构建、活动构建中不存在、形态变化或匹配待核实。仅缺一行记录不能得到删除结论。成员与标量/容器转换、可能改名均保留双方证据。
- `deleted_variables` 只收录已证实删除项；`baseline_only_variables` 保留所有仅基准侧观察到的对象，包括缺口导致的未观察到、构建范围变化和匹配待核实。后者可通过分页证据接口读取，不因此创建新的人工事件或确认资格。
- `risk_transition` 实现 R01 至 R09。新增疑似风险计数只来自 R02；风险可能消除计数只来自具有完整关闭证明的 R04。未知转疑似仍保留当前疑似风险，但不计为本次新引入；未知转安全不计风险修复。新增对象的当前疑似风险单独保留，不强行套入双版本矩阵。
- `SHARED_NO_REVIEW` 有独立转换代码、说明和计数。进入免复核不等于安全或修复，免复核转疑似不计为从安全新引入；证明缺失时标为依据未核实，不能沿用旧豁免。独立核对写者/读者物理上下文、访问角色、原子宽度、对齐、编译器可见性和全部危险条件排除依据；缺项或与当前访问不符均不能继续使用豁免标签。
- R04 的 `closure` 将每个基准冲突的索引、摘要和参与者对应到当前具体安全证明，记录当前全部被覆盖访问及排除的缺口。覆盖访问不齐、有效保护缺失、当前仍有未排除冲突、相关缺口未关闭或基准冲突缺失时均不计修复。冲突引用清单不完整或重复时，也不能计新增/修复。无关 TU 的隔离需要内部链接/无逃逸证据，或所有失败构建变体的完整预处理排除依据；文件名不同本身不是排除证明。
- 新字段进入不可变扫描数据库、变量影响证据、摘要、查询计数及报告包。读取存续对象的基准证明不再要求它先成为删除项；人工确认仍受原删除对象资格检查约束。旧摘要/归档缺少新字段时明确标记 `LEGACY_EVIDENCE`，不将旧变化标签重新解释为新增或修复证明。

**阶段三实施记录（2026-11-19）**

- 记录 Clang 展开后的表达式、局部值传递、参数、返回值、控制条件和调用执行依赖。变更定位到实际读写表达式；同函数的独立操作、共同调用祖先、被丢弃的返回值不自动扩大为明确影响。局部值覆盖后不继续传播旧输入。表达式采用共享节点保存，避免反复引用局部值造成证据体积指数增长。

- 目录过滤仍控制变量归属。范围外函数对目标的指针访问、回调和完整原有访问保持；另保留最小的依赖存储关系，让范围外变量初始值变化仍可到达目标变量。依赖自身的变量不扩入目标清单及三类目标数量。

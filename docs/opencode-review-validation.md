## 修复的问题

- 历史 70 项全部是“自动复核已关闭”，不是模型已审查后的无问题结论。现在已启用真实执行并修正工程位置。
- 给复核包补充完整相关函数，最多 1600 行；明确剩余源码如何按文件路径继续读取，便于检查提前返回、错误恢复和真实临界区。
- 返回的候选 ID 必须完全一致。实测发现模型把 `GS-6fc59d79456ff078` 抄成了 `GS-6fc59d79455ff078`；错误回答保留并拒绝接收，再要求模型重新返回，程序没有代改 ID。
- 新回答必须包含匹配指定源码行的 `quote`。保存源码窗口、文件哈希、实际执行日志；复用缓存和刷新报告时核对原始答案、状态与源码。
- 增加反证复核，检查不存在的抢占关系、指针与被指向对象混淆、遗漏的恢复路径，以及没有源码依据的业务协议。多轮原稿和修订结果均可打开查看。
- 区分实际存储冲突与业务影响：没有额外业务读者不能否认非原子自增丢失更新；原子字节 store/store 的最后写者生效，也不能自动证明业务协议被破坏。
- 报告顶部直接回答总体有无问题，变量结论与独立缺口分别计数。失败、未决和过期记录不算安全，`LIKELY` 不作为已最终定论的缓存。

## 可以直接检查的例子

| 对象 | 最终判断 | 当前源码依据 |
|---|---|---|
| `pending_events` | 有问题 | `serial_service.c:110` 读取快照，`:118` 清零；`:55` 与 `:85` 分别在真实中断路径发布事件。中断在快照读取与清零之间发布的新事件会被一起清掉；两个不同优先级 ISR 的非原子置位还可能互相覆盖。 |
| `tx_frame` | 有问题 | `serial_transport.c:57` 启动 DMA 后，`:58` 立即覆盖同一个缓冲区；DMA 硬件是实际读者。反证轮撤回了首轮关于主循环可在回调未退出时开始下一轮的错误交错，只保留成立的 CPU/DMA 冲突。 |
| `guarded_total` | 当前条件下安全 | `serial_service.c:140–142` 用保存/恢复 PRIMASK 的临界区完整覆盖主循环自增，实际另一写点在 USART2 接收中断路径。 |
| `channel` | 本对象为误报 | `serial_service.c:24` 初始化后，`channel.counter` 没有运行期写入；真正存在非原子 RMW 风险的是其指向的 `rx_watermark`。两者分别归属，后者风险保留。 |

前两个例子还用实际构建的 `serial.elf` 反汇编进行了辅助核对。没有将静态交错分析、建议实验或单元测试冒充板上复现。

## 2026-09-14：复核页面可读性优化

`opencode_review.html` 改为默认展开的变量说明卡：结果、具体执行过程、保护为何不足、修复方向直接可见。风险变量、安全 / 误报、独立证据缺口分别展示；已确认风险优先。源码、日志、历史回答放在卡片底部，源码引用可以直接跳到保存的行号窗口。同一头文件在不同编译单元中的 static 实例显示所属文件，避免同名对象混淆。

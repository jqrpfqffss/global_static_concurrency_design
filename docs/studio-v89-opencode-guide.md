# OpenCode 复核：从配置到查看结论

1. 在“工程配置”中打开工程，返回第 3 步，选择“OpenCode复核”。命令第一行填写 OpenCode 程序路径；模型填已登录的 `provider/model`。同时复核数、超时和重试可逐项设置，未设置项沿用引擎默认。
2. 点击“保存配置并设置复核资料”。在“并发案例库”中选择“工具 config 中的原文件”，或选择自己维护的 Markdown 文件。核对路径和已识别的案例数。
3. 切换“当前工程背景”，选择“编辑工程副本”，写明当前工程的真实入口、硬件配置和已知限制，点击“保存复核资料”。不要写未经核实的安全保证。HTML 模板注释不会送给模型。也可选择自己维护的 `review_context.md` 文件。
4. 开始扫描。若关闭“扫描后自动OpenCode复核”，扫描完成后进入“OpenCode 复核”，点击“复核全部疑似与未知”。每次新任务冻结当时选用的两份资料，任务中心可展开“本任务实际使用的复核资料”核对来源与哈希。
5. 复核完成后进入“OpenCode 复核”。选择“确认风险”“疑似风险”“确认安全 / 误报”或“待复核 / 无法判断”。可搜索变量名或文件，点击变量打开可读的依据、交错过程和处理建议；点击源码位置阅读归档代码。
6. 需要核查模型输入时，展开“复核身份、执行与阅读收据”，查看 packet、提示词和原始响应。“完整原始答复与附加字段”保留全部模型字段。

“确认安全 / 误报”只包含有效复核给出的 REVIEWED_SAFE、FALSE_POSITIVE。安全仍受原回答中条件和覆盖范围限制。技术失败、待复核、证据失效都不表示安全；补好环境后可“仅重试技术失败”。独立覆盖缺口会在清单中明确标识，不当作变量。

修改资料后重新发起复核，使用新的资料快照；恢复中断任务仍沿用原冻结资料，避免同轮混用。复核结果与“人工确认”分别保存，OpenCode 不代替工程师签署结论。

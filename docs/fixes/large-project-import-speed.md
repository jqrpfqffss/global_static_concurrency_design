# 大型归档导入提速、完整性与进度范围修复

日期：2026-11-14。Codex 直接实现、检查和测试，未调用 Claude Code 或 OpenCode。

## 问题与处理

旧导入接口一直等待解包、全库校验和历史合并结束，浏览器没有上传或后台校验进度。同一真实 INAV STM32H743 归档的旧导入耗时 1,383.235 秒（23 分 3 秒）：约 124 秒解包，335 秒数据库完整性/外键检查，632 秒证据哈希检查，剩余约 292 秒用于索引、证据和历史核对及发布。

本次保留所有检查，改变执行方式：

- 解包时同时计算每个文件的 SHA-256，不再写完后重复读完整数据库；保留 ZIP CRC、文件长度、路径、大小/压缩比及空间预算检查。
- 大数据库使用最多 6 个校验进程，按可用 CPU 数限流。完整数据库结构检查、完整外键检查、完整查询索引比较、4 段互不重叠的证据哈希检查共 7 项任务并行调度；每段全部处理，末尾再次断言节点覆盖总数一致。小库仍顺序校验。
- 图校验仍逐节点、逐边计算原有有序类型哈希，有限缓存仅复用相同边的编码字节，重复引用仍计入哈希。未知类型、非法标量尾部、丢失引用、错误顺序和重复键仍拒绝。
- 查询索引按关系流式读取并逐行比较，取消数百万行临时索引重建和每条记录的额外查询。保留 SQLite 类型转换、旧 schema 1/2/3 的调用关系优先规则、全部变量/记录以及遗漏和额外行检查。
- 对已有同 ID 归档，仅当其整个数据库 SHA-256 与本次刚完成全部校验的输入完全一致，且已固定回滚日志读事务，才复用本次检查结论。不同字节或 WAL 仍独立深校验；不依赖旧收据跳过接收端检查。

并行校验仅读取隔离暂存文件。父进程读事务在全部检查结束前固定 SQLite 回滚日志视图；WAL 回退单连接顺序校验。取消、子进程失败或服务退出会停止读取并释放锁，不发布部分归档。接收端不信任包内“已验证”声明。

## 界面与任务

导入改为持久后台任务。选择文件后显示实际上传字节进度，解包显示实际处理字节，证据检查显示实际节点数量及独立检查完成数；不可量化阶段显示阶段名称与耗时。全部证据、数据库和人工历史检查通过并发布后才显示“完整性已验证”。

导入和导出进度只出现在“数据与共享”，均可隐藏、重新显示；切到“历史与对比”等其它页面没有可见进度条。后台任务不占用页面操作，上传完成后刷新可恢复状态。导入成功不会强行切换页面，提供“打开导入归档”和“继续人工确认”。

导入任务支持上传中取消、校验中取消、失败信息和服务重启后的中断状态。上传响应丢失时，仍按持久任务 ID 查询最终结果。重复导入保留双方人工事件，按既有规则去重和保留冲突。

## 实测与验收

测试沿用同一份真实扫描：`scan.db` 12,590,510,080 字节、16,566 项对象、16,913,372 个证据节点、156,776,937 条关系、7,440,345 条查询记录、2,665 个证据文件。输入完整包为 4,196,499,825 字节。原扫描只读；人工续写仅发生在隔离验收目录。

| 完整导入 | 1,383.235 秒（23 分 3 秒，不含上传） | **591.4 秒（9 分 51 秒，包含浏览器上传）** |
| 接收端独立深校验 | 全量串行 | 全量并行，7 项全部通过 |

## 完整性如何保持

1. **保留完整静态数据库。** 对本机完成扫描的 `ECRA_LOCAL_SCAN` 或经本机完整导入生成的 `ECRA_REPORT`，核对已发布收据的工程/扫描身份和数据库结构。导出时流式读取完整原文件，压缩和 SHA-256 在同一次读取中进行；最终摘要必须匹配发布时的整库摘要，否则不发布结果包。不依赖文件名、大小或修改时间判定数据未变。
2. **锁住读取视图。** 回滚日志模式下持有 SQLite 读事务直到打包完成，阻止静态库写入提交。WAL 模式必须使用 SQLite backup，确保包含 WAL 中已提交的数据；没有已发布摘要的归档也保留一致快照和完整深校验路径。
3. **每个新任务重新快照人工记录。** 不复用旧导出包或旧 `reviews.db`，包含快照时刻已提交的确认、修改、撤销、前驱、AI 收据和继承记录。快照之后的新确认继续留在源库，可通过下一次完整包或增量包交接。静态库读锁不会阻止另一个人工记录库正常保存。
4. **全部证据逐字节保留。** 归档源码、审计收据、内容寻址对象以及未被当前页面使用的证据都保留。打包过程中计算每个文件实际写入字节的摘要，证据摘要必须与其内容身份一致。清单最后写入，绑定的是实际入包字节。
5. **接收端独立验证。** 导入不信任包内的“已校验”声明，仍检查全部文件摘要、结构、数据库完整性、外键、证据节点、查询投影和完整人工历史。只有所有检查通过后才原子发布；导出错误、取消或磁盘失败也不发布半包。

快速压缩改为 DEFLATE level 1，标准 ZIP64 格式和导入预算不变。“省空间”仍可选。对同一真实数据库四个 64 MiB 区段的辅助测量中，level 1 / 3 / 6 分别耗时 2.656 / 3.477 / 6.419 秒；整包结果以上表为准。
